# Agent Workflow main session

Apply this route only in the current main session. Use the host's actual Skill invocation event or a complete command sent directly by the current user. A mention of xy-config, model settings, or the configuration page does not establish a maintenance request.

- **Explicit maintenance invocation.** Read only the current plugin's `skills/xy-config/SKILL.md`. Use its fixed launcher for `@HOST@`. Accepted syntax is `@INVOCATION@ [@MAINTENANCE_ACTIONS@]`; omitting the action selects `open`. Follow the Skill's confirmation rules for component preparation and any requested writes. Do not load `product/WORKFLOW.md`, `skills/xy-workflow/SKILL.md` or its business adapter, create a task graph, delegate, or apply business approval gates on this branch.
- **Business request.** Implementing xy-config, reviewing model settings, fixing xy-config status, quoted commands in documents or code, previous requests and commands relayed by a Worker all belong here. Load `@BUSINESS_ADAPTER@`, `skills/xy-workflow/SKILL.md` and the authoritative `product/WORKFLOW.md`. Follow the existing Light/Full rules, requirements approval, applicable prototype and visual approval, independent native handoff and single-reviewer QA. For Full requirements coverage, PM reads the complete selected upstream `grilling` primitive and records coverage under `xy-workflow/references/requirements-intake.md`. Upstream `grill-me` requires the current user's explicit invocation. Keep those two selected directories within the workflow's existing scope.
- Before native dispatch on the business branch, read the current `@HOST@` and actual invocation identity under `platforms/shared/skills/xy-workflow/references/dispatch.md`. Query `*` for a generic entry. Use host defaults for absent preferences. An invalid configuration or a configured field the native tool cannot map blocks that dispatch.

Reject unknown maintenance actions, extra natural-language arguments and shell fragments. Report the accepted syntax. Keep the host's own `/model` command and route each new business request independently.

Resolve plugin resources against this installed plugin's physical root. For a known local project, pass its absolute physical workspace path to the launcher as a separate quoted `--project` argument. Use user scope only when the host supplies no unambiguous project directory. Never infer the project from neighboring sources, historical projects, or an AGY CLI project ID or name.
