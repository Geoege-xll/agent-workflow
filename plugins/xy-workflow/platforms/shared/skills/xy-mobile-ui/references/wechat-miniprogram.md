# 微信小程序平台指导

读取[共享规则](mobile-rules.md)后，确认页面在微信小程序运行时执行。检查项目实际的小程序框架、渲染器、基础库和微信客户端支持范围，复用现有运行时 API 适配与组件。含 `web-view` 的页面沿用现有 Web 指导处理 H5 内部行为，本页处理宿主侧窗口、导航和生命周期。

| 共享条款 | 设计与实现 | 运行证据 |
| --- | --- | --- |
| `mobile-insets-001` | 在契约中注明页面使用原生导航或自定义导航、窗口可用区域、胶囊避让及底栏／键盘的处理层。原生导航由微信宿主管理预留区域。自定义导航用项目已支持的运行时窗口和胶囊信息（如 `wx.getWindowInfo`、`wx.getMenuButtonBoundingClientRect`），在一致的坐标系内分配标题和返回位置；对信息缺失采用项目兼容路径。底部栏按实际窗口和安全区占位。输入组件已经自动上推页面时复用其位移；需要自管布局时按项目实际支持的键盘事件和输入属性统一处理，确定由哪一层负责栏位移及末项滚动空间。 | 在实际小程序窗口核对原生导航／自定义导航适用路径、胶囊与标题和返回按钮。打开键盘并聚焦末项，核对提交栏可达；收起后验证没有重复顶移或留白。依赖客户端输入法行为时，以能重现该行为的微信真机结果为准。 |
| `mobile-navigation-001` | 在契约说明顶级 `tabBar`、细节页面、弹层、编辑返回、分享直达等适用入口。沿用小程序的页面栈和现有路由封装，配置的 tab 页面由 `wx.switchTab` 或宿主标签入口切换，详情返回依据实际页面栈使用 `wx.navigateBack` 或框架对应能力。自定义返回写明无上一页时的项目目标；遇未保存编辑时，只承诺当前框架和客户端可实现的退场提醒与恢复方式。 | 检查实际 tab 切换与详情往返。自定义返回受影响时分别核对有上一页及直达无上一页情况；检查二次退出、标签选中、资料编辑状态和落点。 |
| `mobile-state-001` | 在契约说明首次打开、暂时隐藏后重新显示、卸载重建的恢复范围。沿用页面生命周期（如 `onLoad`、`onShow`、`onHide`、`onUnload`）及现有状态所有者。对只在可见时使用的观察或键盘监听，在相应边界成对注册和清理，清理时传同一个回调；按需求保存筛选、滚动锚点和草稿。 | 往返页面、切换标签或前后台，确认加载和恢复符合契约。重复进入时检查没有多个键盘监听、重复提交或过期数据覆盖。 |
| `mobile-accessibility-001` | 在契约记录长标签、较大字体、触摸范围、读屏名称／状态及适用的动效替代。采用小程序当前渲染器支持的原生控件与无障碍属性。长文字允许换行或为未显示部分保留可读路径，字体增大时主操作仍可达，关键状态使用可读文字和适用语义。自定义动效有无位移或低运动方案时，按客户端和项目实际暴露的设置启用。 | 在受影响的微信客户端场景检查长文字、可用字号设置、触控和系统读屏。核对表单错误、返回按钮和标签选中等实际播报，记录尚未覆盖的设备设置。 |

已有微信开发者工具可用于受影响页面的构建和模拟器检查。需要微信客户端或系统服务的取证，使用项目可用的真机证据并记录客户端、基础库、设备及实际结果。HTML 和普通浏览器只用于演示契约中的状态。来源见[参考来源与许可](sources.md)。
