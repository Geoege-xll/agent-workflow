# Swift 架构案例

在实际 Swift 任务需要判断类型、模块或状态边界时选读。通用方法见[架构设计与增量演进](architecture.md)，官方依据见[来源记录](sources.md#swift)。

## 面向协议与值类型何时适用

- 数据应独立传递时可用 `struct` 组合相关字段。有限且互斥的状态可以用带关联值的 `enum`，让详情数据只出现在加载成功的分支。若成员持有可变引用，检查复制后是否仍会共享状态。需要共享身份或由框架管理生命周期时，沿用已有的引用类型和状态所有者。
- 存在明确的替换点时，可让调用方依赖小型 `protocol`。把遵循者需要自定义且要经协议调用的行为声明为协议要求，同时可在扩展中提供默认实现。只写在协议扩展中的同名方法属于辅助方法，经协议类型调用时按扩展选择。只有一个稳定实现时，可直接使用具体类型或函数。
- 例如详情页在生产环境确实支持网络和本地两种加载方式时，可用协议描述共同的加载与错误语义。沿真实入口验证各实现都能更新同一份页面状态，并在经过协议的调用点确认使用了预期实现。若只有一个加载方式，可直接调用现有加载器，用值类型表达加载中、成功和失败。

## SwiftUI 详情页的视图依赖

Apple 在 WWDC 的 `DogView` 示例中，将姓名、品种和图片分别传给 `DogHeader` 与 `ScalableDogImage`，从调用处可以直接看出各子视图依赖哪些数据。应用这个做法时，如果详情页头部、图片视图和短小的展示辅助只服务于同一页面，且随页面一起调整，可在同一个 `DetailView.swift` 保留多个 `private` 视图类型。当另一页面也需要相同图片交互，确认输入、失败表现和资源生命周期一致后，再考虑提取。文件位置由职责和调用关系决定。Apple 的演讲讨论的是 SwiftUI 更新依赖和测量。

- 只让需要的调用方看到入口。应用模块内的页面入口可沿用 `internal`，单文件的视觉细节可用 `private`。确有跨模块调用时，按项目 Swift 版本和包结构选择合适的可见性。用真实调用读一遍参数标签，说明输入、输出、错误、取消和有意义的副作用。
- 页面可持有展开项等页面内状态，小视图接收必要数据和动作。若还需刷新详情，沿项目现有模型或服务发起请求，明确谁持有和取消任务、谁发布结果以及失败如何回到页面。
- 从真实导航入口核对详情展示、适用的失败和重试，异步切换时检查旧结果是否会覆盖新页面。若拆分是为了解决频繁或昂贵的更新，在相同设备或模拟器与交互条件下测量改动前后。
