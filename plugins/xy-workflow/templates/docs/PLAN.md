## 需求与验收

从一个可复现的场景写起：谁在什么条件下做什么，会看到什么结果。写下读者能实际验证的通过条件。失败会影响下一步时，说明反馈、保留的数据及恢复去向。存在实质取舍时，先记录建议与影响，确认后原位写明决定与依据。

需要原型时沿用稳定 REQ ID。交付后链接具体 HTML 及状态锚点；页面可回到本主题的规则章节。引用规范、架构或批准材料时，使用有含义的相对链接，仅引用与当前场景有关的部分。
