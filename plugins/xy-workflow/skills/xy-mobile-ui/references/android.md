# Android 平台指导

读取[共享规则](mobile-rules.md)后，确认页面实际采用 Compose、Views 或混合容器，以及项目的编译／目标 SDK、最低支持 API 和已有 Jetpack 版本。按当前窗口模式、系统栏策略和基线能力实施与验证。

| 共享条款 | 设计与实现 | 运行证据 |
| --- | --- | --- |
| `mobile-insets-001` | 在契约中标注状态栏、导航栏、输入法（IME）与应用底栏分别影响哪个区域。Compose 先确认 `Scaffold` 的栏及内容边距所有者，应用传入的 `PaddingValues` 后按需要消费对应 Insets，再处理剩余的系统栏或 IME Insets。Views 复用现有 `WindowInsetsCompat` 传递和 IME 策略；以初始边距或内边距为基线更新布局。混合容器先核对宿主和渲染子树间的处理边界。 | 按项目受支持的边到边配置、导航模式和窗口验证。开合 IME 并聚焦最后一个字段，检查布局没有重复上移或多留空白，列表末项和主操作仍可达。手势／三键模式结果可能不同且受影响时再补测。 |
| `mobile-navigation-001` | 在契约中区分工具栏向上导航、系统返回、顶级标签切换和临时覆盖层。沿用项目导航栈。系统和当前依赖支持预测式返回时，复用已有 Navigation 支持或相容的返回分发 API（例如 `OnBackPressedDispatcher` 或 Compose 的返回处理器）。自定义处理只在对应状态启用，手势取消不执行退出或丢弃，完成时才提交导航。 | 依据实际系统版本、应用配置和受影响路径，验证返回目标及状态恢复。支持预测式返回时检查预览、取消及完成，必要时核对项目仍支持的不带预测动画的返回路径。 |
| `mobile-state-001` | 在契约中写页面可见状态及配置变更、返回和需要支持的进程重建行为。Compose 对 `Flow` 按生命周期收集，项目已支持时可用 `collectAsStateWithLifecycle`；Views 可用现有的 `repeatOnLifecycle` 及正确的视图生命周期绑定。根据项目实际状态所有者使用已有 ViewModel、保存状态或持久化机制恢复约定数据。 | 从选定的配置变更、页面往返或前后台，验证加载和状态恢复。检查页面离开时收集边界以及返回后不会重复注册或重新触发已完成的用户操作。 |
| `mobile-accessibility-001` | 在契约中写触控范围、字体缩放、读屏和适用的减少动态效果表现。Android 指导建议交互目标至少 `48 × 48 dp`。Compose 检查材料控件的交互尺寸和可访问语义，Views 检查实际最小命中范围和无障碍元数据。文字使用支持系统字号缩放的样式或 `sp`，让布局随内容增长。自定义动效按当前平台与组件支持的动画设置保留可用反馈。 | 用较大字体、触控和 TalkBack 核对最后一项、主操作、选中状态和读屏顺序。核对相邻目标能分别触发。改动动效时验证系统动画缩减配置下的操作结果。 |

沿用项目实际支持的 Compose／Views、系统版本和库。来源见[参考来源与许可](sources.md)。
