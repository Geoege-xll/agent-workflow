# iOS 与 iPadOS 平台指导

读取[共享规则](mobile-rules.md)后，按页面实际使用的 SwiftUI、UIKit 或混合容器查找负责层。以目标的 SDK、最低系统版本和已有组件为依据。设计在开发说明中补充下列已确认且操作后仍无法确定的行为，实现与 QA 核对具体场景。

| 共享条款 | 设计与实现 | 运行证据 |
| --- | --- | --- |
| `mobile-insets-001` | 在契约中说明窗口范围、系统栏下可延展的背景、固定底栏、输入焦点和键盘开合后的滚动。SwiftUI 优先利用容器安全区，支持时可用 `safeAreaInset` 为底栏留出空间，让忽略安全区的修饰仅作用于须延展的背景。UIKit 复用 `safeAreaLayoutGuide` 和滚动视图的系统 inset；支持时用 `keyboardLayoutGuide` 或现有键盘协调逻辑按受遮挡区域更新约束。混合页面先检查宿主导航／标签栏和子视图已经处理的边距。 | 在目标 iPhone 或 iPad 窗口打开键盘并聚焦末项，核对输入、错误信息、底部主按钮所在范围。核对收起后无重复空白。支持多窗口或其他键盘形态且受影响时，补窄窗口、悬浮／分离键盘或外接键盘验证。 |
| `mobile-navigation-001` | 在契约中写清顶级入口、返回层级和交互式取消的结果。复用项目现有 SwiftUI 导航或 UIKit 容器和模态关闭行为，定制返回时保留适用的系统交互。iPadOS 使用不同导航布局时，明确目标与选中状态如何对应。 | 用返回按钮和适用的边缘返回手势走详情或关闭路径。改变交互式过渡时确认取消保留原页、完成仅回退一层，导航与草稿状态符合契约。 |
| `mobile-state-001` | 在契约中分别写明编辑中、暂时不可见、重新进入和支持的恢复行为。SwiftUI 将渲染与副作用分开，依据现有所有者和场景选择可观察状态、页面任务及恢复方式；UIKit 按控制器／场景生命周期管理观察、异步任务和恢复。确认页级、场景级与持久草稿的保存边界。 | 复用现有测试或在适用的返回、后台前台、窗口重建中观察恢复和刷新。确认提交流程仅执行一次，退出后的迟到结果没有改写新打开的页面。 |
| `mobile-accessibility-001` | 在契约中记命中范围、Dynamic Type 下重排、VoiceOver 语义和适用的减少动态效果。Apple HIG 给出 iOS／iPadOS 的默认控件尺寸 `44 × 44 pt`，同时区分推荐的最小控件尺寸；优先沿用原生控件，并按上下文核对真实命中区域及间距。SwiftUI 采用支持 Dynamic Type 的文字样式和原生语义；UIKit 按项目方式匹配可缩放字体和 `UIAccessibility` 语义。自定义动效适用时读取系统减少动态效果设置并提供低运动表现。 | 在影响的页面设置较大 Dynamic Type，检查标题、输入和主操作的可达性。用 VoiceOver 验证名称、角色、值及焦点返回；适用时打开减少动态效果后重走交互。 |

保留系统控件行为与当前最低系统版本的可用路径。SwiftUI 专用 API 需要额外核对时，可按需使用已核验的 `xy-apple-guidance`。来源见[参考来源与许可](sources.md)。
