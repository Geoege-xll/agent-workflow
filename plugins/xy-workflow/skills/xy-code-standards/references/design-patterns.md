# 设计模式案例

按当前问题选读这十二个自编案例。按 [通用工程规则](rules.md) 的 `eng-common-013` 判断抽象的收益，按 `eng-common-009` 从真实入口核对调用方看到的结果。已有入口、局部函数或直接构造能表达当前契约时，可以就地实现。涉及外部输入、状态写入和资源释放时，可继续查阅[边界判断](boundary-reasoning.md)。出处和采用范围见[案例来源](sources.md#设计模式案例)。

先确认项目已采用的架构、实际依赖、支持版本和本次批准范围。优先参考适用于当前语言、框架和版本的官方建议，再在既有边界做必要扩展。升级 SDK 或改变已确认的架构时，沿用项目现有批准流程。

例如，支持 Observation 的 SwiftUI 项目可以让视图直接观察数据模型，项目需要独立组织页面状态时也可以选择 MVVM。Android 官方建议在收益适用时用 Jetpack `ViewModel` 提供屏幕级状态，可复用组件可用普通状态持有类。出处见 [Swift](sources.md#swift) 与 [Kotlin](sources.md#kotlin) 的平台资料。

## 适配器

订单导入接入两家供应商，金额单位和错误码各异。可在导入边界把外部数据和错误映射为业务契约，由导入流程负责业务判断。差异只涉及调用处的一次字段转换时，现有映射函数即可。从实际导入入口核对同一金额的不同表示能得到等价的业务结果，非法数据在写入前被拒绝，外部失败按项目契约返回。`eng-common-008`、`eng-common-010`

## 策略

待办列表允许按截止时间或优先级排序。排序规则会独立演进或供多个入口使用时，可以给排序入口传入遵守同一比较契约的函数。固定排序或一个清楚的局部分支可直接实现。从实际列表入口核对两种顺序、并列和缺省值的处理，以及无效排序参数的返回。

## 状态机

状态机用状态、事件和允许的转换描述流程。GoF 状态模式用不同的状态对象承载随状态而变的行为，可在这些行为需要独立演进时用于实现流程。后台任务若只需集中判断完成、失败和取消等事件，枚举和处理事件的局部函数即可。

任务明确执行失败时走失败路径。结果写入超时且提交结果未知时，按项目契约报告待确认，再查权威来源或用同一操作标识进行受支持的幂等恢复。取消已确认且按契约该次操作未产生写入时，可拒绝迟到的完成通知。取消还在请求阶段或写入结果未知时，先查权威状态，并按项目契约处理已提交的结果。

从执行和重试入口核对完成、失败、取消与提交交错时的实际结果。重复投递时检查是否只提交一次业务结果，防重复由项目的事务、条件写入或幂等机制落实。`eng-common-017`、`eng-common-025`、`eng-common-026`

## 工厂

多个导出入口需要按格式选择写入器，并为每次导出创建独立的可变实例时，可以交给工厂。已有启动入口负责集中装配并传入存储客户端与配置，资源由持有它的作用域管理。实现固定且构造简单时，可以直接构造并传参。从启动和导出入口核对实际输出、无效配置或格式的错误、连续导出的实例隔离，以及失败时本次输出流的释放。`eng-common-010`、`eng-common-017`

## 外观

页面和命令都要为下载报表执行取数、渲染和文件交付时，可给调用方提供一个报表下载入口协调这些步骤，业务校验交给原有服务。已有一个服务调用能完成任务时可以直接复用。从实际下载入口核对返回文件的内容，以及模板加载失败时返回的错误。

## 装饰器

不同导入流程希望按需统计读取字节数时，可包装已有读取接口，在读取时累计字节并按原契约传递数据和错误。只有一个入口需要统计时，局部计数即可。从实际读取入口核对读出的字节和计数，并确认读取失败后底层流按约定释放。`eng-common-017`

## 观察者

列表和统计模块都需要响应库存更新时，可由库存模块发布变更通知，各订阅方自行刷新并在生命周期结束时解绑。只有一个固定的后续动作时可以直接调用。从实际库存更新入口核对两个订阅方都收到通知，再触发一次更新，确认已解绑的订阅方停止接收。`eng-common-017`、`eng-common-025`

## 责任链

上传入口需要按顺序检查文件类型、大小与配额，且不同入口要组合不同检查时，可组成有序的处理链，由每环决定继续或拒绝。顺序固定且只在一处使用时，按顺序调用即可。从实际上传入口提交同时触发多项限制的文件，核对首个约定错误，并确认类型拒绝在查配额和写入前结束流程。

## 命令

菜单和快捷键都需要发起文件移动，且操作需要排队执行时，可把源文件和目标位置封装为命令，由已有执行入口校验权限并提交移动。若点击后立即调用服务即可，直接调用。从菜单或快捷键执行，核对目标位置、权限失败的反馈和实际写入。业务承诺可撤销时，再核对恢复位置及目标冲突时的行为。`eng-common-026`

## 建造者

报表请求的列、分组和导出选项分步确定，且选项之间有组合约束时，可由建造者收集参数并在生成请求时校验。参数固定且能一次传齐时，直接构造即可。从实际报表入口核对列和分组的输出，以及启用分组却缺少分组列时在查询前返回的错误。

## 组合

文档和目录需要通过同一个入口计算文件数时，可让文档提供自身计数，目录以同一操作汇总其子节点。数据只有一层时，直接处理文档列表即可。从实际目录入口核对空目录和多层目录的计数，包含文档与子目录混合的情况。

## 代理

多个下载入口经同一代理访问实际存储时，可由代理在转发前复用项目的授权判断。已有下载服务能统一校验这些请求时，直接调用该服务即可。从真实下载入口核对有权请求取得文档、无权请求被拒绝。代理带缓存时，准备两个租户各自有权访问、ID 相同但内容不同的文档。让两个租户依次从真实下载入口请求各自文档并填充缓存，再重复请求或以相反顺序请求，核对每次都返回对应租户的内容。也验证缓存命中的无权请求在返回内容前被拒绝。`eng-common-015`、`eng-common-025`
