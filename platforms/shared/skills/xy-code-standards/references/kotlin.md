# Kotlin 架构案例

在实际 Kotlin 任务需要判断源码组织、公开接口或协程归属时选读。通用方法见[架构设计与增量演进](architecture.md)，官方指南和固定上游示例见[来源记录](sources.md#kotlin)。

## 用函数、密封类型和委托表达职责

- 无须持有状态的映射、转换或校验可优先用函数，随所属业务放置。状态集合有限且各状态持有不同数据时，可用项目版本支持的 `sealed class` 或 `sealed interface`。例如内容加载的成功状态才持有数据，失败状态持有可用于恢复的信息。用穷尽的 `when` 表达处理分支，从实际入口核对成功与失败后的展示或重试。
- 已有接口的多项操作确实需要转发，且仅少数行为需要定制时，可考虑用 `by` 委托复用现有实现。简单调用可直接组合具体函数或对象。采用委托时，核对调用方直接调用覆盖方法和被委托对象内部调用自身方法时的行为。

## 按调用者和协程生命周期组织实现

- 可将语义紧密的类型和函数放在同一个文件。某调用方专用的短小映射或扩展可用文件内 `private` 声明。需要共享且输入、输出和失败语义一致时，按实际调用范围选择模块内 `internal` 或项目已有的跨模块入口。
- 在已经使用协程的项目中，让挂起调用在归属明确的作用域内完成。调用者若要等待、取消或处理失败，在接口上保留这些语义。需要跨调用者生命周期继续运行的工作由已有的长期任务所有者接管，并明确终止和失败处理。并发行为变化时，用真实入口检查取消或子任务失败是否留下重复写入、迟到结果或未释放的资源。

## Android 平台实例

Now in Android 的「For You」导航入口调用 `ForYouScreen`，入口收集 `ForYouViewModel` 的状态并把状态与事件交给同文件的 `internal` 重载。收藏事件回调到 `updateNewsResourceSaved`，`ViewModel` 在 `viewModelScope` 内调用 `UserDataRepository`，现有测试通过仓库替身观察收藏和取消收藏的状态变化。界面渲染与短小的展示辅助仍可随同一页面组织。变更这条链路时，可沿同一入口检查项目约定的写入失败表现和离开页面后的行为。示例中的 Compose、`ViewModel`、依赖注入和 Gradle 模块布局取决于该 Android 项目。
