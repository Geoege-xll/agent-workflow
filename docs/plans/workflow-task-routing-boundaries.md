# 任务等级与 PM 实施边界优化

## 批准与目标

用户已澄清：保留现有 Trivial／Light／Full 任务等级；简单任务允许 PM 直接实施，
Light／Full 默认派对应 subagent，明确指定 PM 亲自实施时才例外。
用户随后明确回复“开始优化”，授权落实本计划，不再重复请求同一需求确认。

本轮属于跨宿主共享工作流指令修正，按 Full 实施；非 UI，无原型选择。
需求覆盖已完整：现有规则、会话审计及用户澄清足以规划，没有待补的实质问题。

## 范围与方案

- 规则线：在现有 WORKFLOW、xy-workflow、派发／恢复细则、共享入口和三宿主说明中
  澄清分级后的实施者选择；保持 Trivial 主会话局部验证、Light 精简规划、Full 原门禁。
- 明确 PM 实施例外须来自用户对当前任务及范围的真实指令；普通“帮我优化／开始／继续”
  不构成该例外。例外只改变实施者，不免除原验证与独立 QA；角色不可用或失败不自动授权接手。
- 压缩恢复保留当前任务等级、有效批准、原 Agent 与证据；不将摘要里的例外陈述独立当作授权。
  优先复用当前可见的原始指令和现有计划引用，缺失时只恢复相关事实，不默认扫描整个历史。
- Hook 线：消除“不自动新增 QA”的歧义，明确保留既有必需验证与 QA；保持有界、只读、
  中性失败与可关闭的辅助层，不增加任务分类器、执行拦截、监督 Agent、权限账本或新门禁。
- 在已有测试文件补实际覆盖缺口，并核对真实生成／安装消费者；同一独立 QA 审计全部变更，
  返工仅复查实际变化的范围，不重跑有效证据。

PM 负责本计划、任务包、协调、证据核对及收口。规则与 Hook 分别由独立实现 Agent 修改，
每个路径只有一个 Writer。保留前两批优化、原生审查顺序、CAS／锁、安装保护及用户配置。
本轮不变更项目适配器、业务代码、数据库、宿主模型／权限；外部发布和业务项目安装另按明确授权执行。

## 验收与验证

- Trivial 小改／低风险文案仍可由 PM 直接实施，不自动增加计划、Agent 或独立 QA。
- Light／Full 普通实施请求默认派发；真实且范围明确的 PM 实施指令只改变对应实施者。
- 十二页原型深度改版、共享样式和公共合同不得因“功能不变／改动少”降为 Trivial。
- 恢复不新增授权、不重启已完成工作；无法确认的例外不能靠摘要补造。
- Hook 的真实回调覆盖 Codex／Claude／AGY，关闭、异常、身份隔离、注入长度和原生信任保持。
- 规则／Hook 相关定向测试和必要三宿主生成／安装检查通过，完整命令、退出码及失败留在本轮证据。
- QA 在原有唯一审查者与方法选择顺序下核对源码、规范、证据，并给出有效交接；
  行为场景抽查与静态安装检查分别说明，不声称跨模型普遍服从。

## 文档与交付

规则和使用说明随对应实现原地维护，不另造规范叶或规则副本。
本仓没有配置完成态业务 PROJECT／feature 内容，本轮无需投影业务功能事实。
QA 后评估精确本地提交；不把完成本轮优化解释为新的远程推送或业务项目同步授权。
