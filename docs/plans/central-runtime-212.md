# 中央运行时统一管理与原生角色继承

- 主题 ID: `central-runtime-212`
- 阶段: `active`
- 模块: `.`
- 任务等级: `Full`
- 已验收版本: `none`

## 目标与范围

将 2.1.1 已有不可变核心、任务固定版本和逐字段模型继承整合为 2.1.2 的统一中央管理机制。CLI 是管理入口，TUI 使用相同服务；一次激活中央版本即可更新启用且跟随的项目。生产实现由职责明确、仅接收当前交接的独立子代理完成。

不改变既定 PM／实施／验证／独立 QA 流程，不实施立项讨论入口，不恢复 npm/npx 或 Windows 安装，不引入常驻调度器、数据库、运行中 Agent 池或旧自包含安装兼容层。业务文档、有效旧任务 pin、用户偏好和主工作区五处既有未提交修改保留。

## 需求与验收

1. 中央 current 与项目实际 binding 分离；项目默认 follow，显式 use 锁版，follow 恢复跟随。停用项目不因中央激活重新启用，下次启用采用有效策略版本。
2. 全局激活／回退固定受影响集合、重查前像、逐项目结算并支持条件补偿／中断恢复；失败不得虚报全部成功，不覆盖并发编辑。新任务初始化与激活共用短协调锁，旧任务显式 pin 继续按原核心读取。
3. 三端原生全局 subagent 由精确归属管理；项目按实际覆盖或宿主策略生成完整稀疏投影。优先级按字段为项目覆盖、通用同角色默认、宿主／会话；显式 inherit 直接选择宿主。内置 Skill 保持项目内单一源和宿主发现软链，任务正文仍由 pin 读取。
4. TUI 新增中央状态、激活／回退和项目跟随／锁版；当前项目、当前平台全部角色一键恢复通用默认，真实清除覆盖。独立预览，取消保留草稿，确认后仅结算本提案草稿，无改动明确提示未写入。
5. 健康区分声明启用、当前资源、历史恢复能力、新任务许可和管理写许可。历史备份缺失不得伪装当前停用；未知手改不得当作可清理备份。doctor 区分资源一致、宿主发现证据和真实模型执行证据。
6. 备份生命周期保留最新完整批次和未结算恢复依赖，原 applied journal 事实不改写；旧核心保守保活 current／previous／项目实际与 used／pin／事务引用，未知引用不删除。暂停的旧清理脚本不执行，重新通过统一服务计划。
7. 默认正式命令来源唯一为 Homebrew，源码开发显式入口；核心导入、中央激活、程序升级分别表达。独立 QA 通过后发布 GitHub／Tap 2.1.2，升级本机并让 mt-shop、ParentsKit、TeachingAssistant 跟随中央最新版，核实文档、偏好、旧 pin 与历史遗留。

验收覆盖 follow／pinned／disabled 混合、第二项目失败、预览漂移、发布中断、初始化竞态、旧 pin、历史缺失与真实手改区分、全局角色冲突和临时宿主路径隔离、模型逐字段继承与整平台恢复、真实 PTY 键盘和窄屏／单色。必要 CI 和实际打包安装验收保持；原生宿主无法执行时明确证据限度，不用配置检查冒充模型执行。

## 方案与原型关联

三部分只读架构分析已完成。沿用已确认的 curses 粗外框、虚线项目分隔、顶部平台 Tab 和左右区域焦点；新增管理动作复用现有菜单、滚动预览与结果弹层。此次是交互变化，采用 UI-Flow；用户明确“分析完成后，直接开工，按照有UI规范不设计原型图”，本范围 prototype_policy 为 waived_by_user。不创建或改写历史原型，工程／设计规范、真实 PTY、UI 和可访问性 QA 保留。

保留封闭 binding schema 1 和三字段任务 pin。新增 current／policy／activation／native ownership 旁路记录；不将机器配置塞入核心或任务 pin。全局宿主路径作为显式冻结上下文注入，临时 state 不得隐式写真实 HOME。角色 bootstrap 先读任务 pin，再读固定核心正文，不预载可变 Skill 技术正文。

生效原生根授权归 current 的 native_roots，随 generation 同次条件发布；最后一次 activation 仅记录事务过程，失败批次不得遮蔽旧 current 的准入权威。原生补偿的新建执行与中断恢复共用同一有界状态推进，先核归属再继续已登记的 stage／held／result；已证本轮节点可以推进，未知节点继续保全并报冲突。

current 还必须具有本版中央控制协议资格。控制器协议与任务初始化 helper 的准入协议相互独立：历史核心可以继续服务固定任务资源，helper 0 可以由新控制器持父锁调用，但缺少受支持控制协议的旧核心不能被激活或回退为 current。选版前静态核验声明，薄入口在完整验证核心并加载 bridge 后再次核验控制动作；不改 binding／manifest 格式，不增加旧控制器兼容实现。

实施分两层：先并行完成中央控制与生命周期服务、原生角色及偏好服务、正式／开发入口；再在整合后的服务上实现 CLI／TUI 适配与文档。每个文件同一阶段只有一个 owner，生产代码由子代理修改；PM 仅计划、集成、验证与发布。后置独立 QA 审计完整组合差量。
