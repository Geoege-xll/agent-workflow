# 通用开发规范与架构设计

- 主题 ID：`code-architecture-guidance`
- 阶段：`completed`
- 模块：`xy-code-standards` 通用规则与按需参考
- 任务等级：`Full`
- 已验收版本：`3.0.7`

## 目标与范围

给所有开发角色提供可执行的架构判断，涵盖职责拆分、依赖方向、公开边界、状态和副作用归属，以及重构后的行为验证。用官方指导和维护活跃的开源项目支撑规则，补充 Swift、Kotlin、Python 与 Go 的按需案例。

## 需求与验收

- REQ-001：复用现有通用规则 ID。在涉及真实架构决策时，用职责、依赖、状态和验证边界判断是否拆分。保留职责单一的文件和紧密协作的私有实现，按业务事实控制拆分范围。
- REQ-002：新增或改变共享封装时优先从真实调用点验证易用性，说明输入输出、错误、取消及依赖归属。缺少可访问且获准验证的真实调用方时，按 REQ-007 验证正式入口。明确何时应复用、提取或保留本地实现，按实际收益选择模块边界和依赖倒置。
- REQ-003：通用架构参考给出增量演进方法。涉及公开接口、数据或部署边界时，明确现有消费者与迁移风险，依据真实入口验证成功及适用的失败与恢复行为，沿现行计划和 QA 交接保留必要结论。
- REQ-004：Swift、Kotlin、Python 案例仅按实际技术栈读取。记录真正使用的官方文档和开源参考，开源示例引用固定提交及许可证。三宿主实际插件包能读取完整参考，保留原有角色和验收合同。
- REQ-005：增加一份按需设计模式知识参考，覆盖适配器、策略、状态机、工厂、外观、装饰器、观察者、责任链、命令、建造者、组合和代理。每例说明实际问题、可保持简单的情形和可验证的结果。根据实际语言、框架和版本优先参考官方指导，再按项目现状合理扩展。沿用现有规则和 QA 交接。选集为项目自编。
- REQ-006：将 Swift、Kotlin、Python 与 Go 的官方惯用法分别纳入对应的按需参考。Swift 说明面向协议与值类型组合的适用条件，其他语言分别以各自的类型、状态、资源和包边界为依据。验证来源、技能入口、三端装配，以及通用规则与语言参考的边界。
- REQ-007：修复严格审计的四项发现。为新旧公开入口明确无可访问真实调用方时的验证方法，为插件参考明确规范资源路径，为代理示例补充双租户同 ID 缓存隔离检查，并记录最终候选的验收与来源证据。
