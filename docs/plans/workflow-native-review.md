# 原生审查优先与 QA 技能精简

状态：已完成中央源包优化与独立验收。用户在本会话认可“原生能力优先、缺口按需扩展”，并明确要求开始优化。

## 范围与边界

本轮修改中央工作流源包的 QA 方法交接校验、宿主接入说明、QA 技能及角色说明和相关测试。
保留唯一独立 QA、只读权限、请求级固定范围、规范覆盖、强制验证、PM 返工与既有收口。
业务项目同步、客户端升级、远程发布、自动修复和 PR 评论不属于本轮范围。

源包自身使用 `templates/docs/STANDARDS.md` 和 `templates/docs/standards/GENERAL.md` 作为
工程基准；不为维护源包生成一套业务项目文档。现有 product、role、skill 即本轮需更新的
权威使用说明，没有另外的 PROJECT／feature 投影需求。

## 实施决定

- 继续使用 `host-native-review`、`installed-code-review-skill`、`internal-xy-qa-procedure`
  的既定顺序；只有技术不可用可以回退，发现缺陷或 FAIL 交 PM 返工。
- 复用 `review_method`：校验方法枚举、具体外部技能、非空能力／回退证据、合法回退原因
  及方法间一致性。原生方法的回退原因必须为空；后续方法必须说明前序技术不可用。
  不添加另一套运行记录，不把字符串证据的格式校验冒充真实能力验证。
- 宿主说明给出原生审查的固定范围、只读和前台兼容要求，识别命令覆盖／禁用情况，
  沿用项目模型与 effort；无法安全使用时记录真实原因后沿原链回退。
- 通用代码审查优先消费原生结果；QA 复核发现并补审项目验收缺口，不重复启动完整同类
  审查。角色保留身份与边界，专项细则按需读取；保留全部原有验收和设计权限约束。

## 工作与验收

1. 校验实现者负责 `lib/qa_handoff_cli.py`、`tests/test_qa_handoff.py`，验证未知方法、
   缺失证据、方法／外部技能／回退原因冲突及合法三种方法，并验证真实 CLI。
2. 指令实现者负责 QA 技能、角色、必要宿主说明和权威合同，对齐上述固定接口；
   复用现有宿主／统一工作流合同测试，调整仅因入口精简而变化的合法加载位置。
3. 两部分在已冻结接口下独立实施，共享同一源树且文件不重叠；完成后核对实际集成
   差异与生成物，再由唯一独立 QA 审查。采用请求 scratch 保存完整日志与内部交接。

验收包含交接 CLI 定向回归、受影响宿主合同／安装检查、技能 frontmatter 和引用检查。
不默认执行全仓测试，不将历史失败弱化为通过。真实原生模型调用与 token 费用节省需要
独立运行证据，本轮不得用静态帮助或替身宣称已经端到端验证或已经降低费用。
