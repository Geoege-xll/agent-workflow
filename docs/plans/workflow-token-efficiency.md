# 工作流 token 效率优化与三项目同步

状态：已完成。确认依据：2026-10-31 本会话，用户在会话抽样审计后明确要求开始优化，并完成后同步 mt-shop、TeachingAssistant、ParentsKit。非 UI 任务，无原型选择。

## 目标与边界

落实审计中优先级最高的三项：提供不会静默漏读的长文档分页工具；压缩 Codex 静态角色中重复的发现上下文并保留可核查的完整事实；为现有任务图提供严格、机械的初始化／组装入口，减少手写固定字段和重复纠错。补充相关使用说明，复用既有 Task Pack 导出和有效验证证据。

保留任务分级、需求与适用视觉确认、精确写入权、规范覆盖、构建与可运行底线、同一位独立 QA 和受影响范围返修。工具不得自行批准、猜测适用规则或制造通过。保留前两轮未提交修复，不改业务功能、业务数据、项目配置、模型强度或原生权限。优化和同步阶段不自动提交或推送，后续明确发布授权见末节。

## 实施与验收

- 长文档读取：标准库工具按连续位置、内容指纹返回有界内容及明确后续位置；验证中文、长行、完整重组、文件变化和不安全路径。文档明确每位 Agent 独立读取必需规范，分页不增加工作流门禁。
- 角色上下文：复用发现器，合并重复的技术栈／验证候选而保留每个模块的准确目录、证据和命令映射；不改变角色集合、权限和事实更新策略。验证语义等价、差异化命令和多模块体积变化。
- 记录工具：扩展既有 CLI，显式输入 PM 决定的任务／规范／授权事实，机械生成固定字段及指纹后复用原校验器；拒绝缺失或不合法的授权与规范，不改旧图读取合同。验证真实生成、旧调用兼容和失败不发布。
- 三项作者返回真实定向验证与可运行证据后，由同一位只读 QA 审查集成结果；已确认的历史英文生成物合同失败不得通过弱化断言消除。

## 同步与恢复

源包通过后，顺序使用现有受管安装器升级三个指定项目，并验收各宿主生成结果。先核对受管清单和项目自定义内容，保留原配置、用户 Hooks、权限、业务文档与未提交代码。同步失败按原事务恢复；并发或用户修改冲突不得强行覆盖。已有 Agent 与任务不重启、不重放，原生宿主缓存的生效边界如实报告。

只更新工作流 README 和相关已有指令说明；不为本任务更新三个项目的业务 PROJECT／功能事实，不增加状态台账。完成后仅清理本轮不再被证据引用的临时产物。

## 完成结果与验证边界

三项已实现并由同一位独立 QA 审查通过：固定 14 个实现／说明文件，覆盖 32 条必需规范与 2 条建议规范，既有 `qa_handoff_cli.py validate` 验收成功。相关测试去重后 96 项通过；保留原始失败记录，文档并发变化和旧路径字面断言修正后仅重跑受影响用例。没有弱化全英文生成物的历史断言，也未执行无关全仓测试。

角色发现上下文保留全部事实，在 grouped 和 flat 两个完整格式中选短。三个项目全部 16 个启用角色独立展开等价，均未超过相同发现输入的旧表示。backend／QA 的字符数分别为：mt-shop 9644→2836／16143→5223，TeachingAssistant 908→590／2079→1626，ParentsKit 740→578／9168→5597。字符对照不是实测 token 或费用节省。

三个项目均经原安装器完成升级及三宿主检查。每个项目的九个核心实现／指令文件与源包一致，全部 Codex 角色上下文匹配当前发现事实，新分页和 init CLI 安装态冒烟通过。项目配置、用户自定义指令、用户原生设置、模型／沙箱选择、PROJECT／STANDARDS 与功能目录 Markdown 文件保护核对均一致；未重启业务服务或 Agent，不重放业务验收。

完整实现命令、日志、尺寸与规范覆盖保存在本会话实现者／QA 交接及同一请求的保留证据中，三项目同步日志和保护核对结果可复核。测试夹具已清理；为避免失去完整验收证据和前轮未提交差异的恢复能力，保留当前请求必要日志、指纹及初始差异。三项目的升级恢复备份保留，缺少完整原始指纹的历史备份未强行删除。

优化和同步阶段未提交或推送，与前轮未提交修改一并保留供后续统一处理。没有新增记忆／状态台账或修改业务功能文档。文件同步不会强制刷新已运行会话的内存上下文，实际加载遵循各宿主正常重载机制；原生 Windows 行为和实际 tokenizer／计费降幅未作保证。
