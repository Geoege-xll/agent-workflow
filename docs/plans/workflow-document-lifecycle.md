# 3.0 主题文档与原型评审工作区

- 主题 ID：`workflow-document-lifecycle`
- 阶段：`completed`
- 模块：主题文档、原型模板、反馈输入与修订交接
- 任务等级：`Full`
- 已验收版本：`3.0.0-alpha.9`

## 目标与范围

提供单一主题 Markdown 生命周期、高保真原型评审与增量反馈，以及随插件维护的通用离线评审工具。当前基线 alpha.9 包含最初 alpha.7 节点反馈和 alpha.8 资源归属升级；不再把已经发布的源码称为待发布候选。

借鉴外部项目的稳定节点、分级反馈和局部修改交接，保留两步确认、唯一独立 QA、需求 Markdown 权威及原生角色职责。通用工具由插件交付，项目只保存具体原型、业务 CSS／JS、需求和设计规范。三个业务项目实际迁移尚未执行。

不引入拖拽编辑、通用 JSON 页面渲染器、HTTP 常驻服务或模型 MCP；不恢复计划 HTML、TUI、旧中央运行时、npm／npx 或退役 2.x 直装兼容。Windows 暂停。

### 插件统一评审工具

- **REQ-201：资源归属。** 导航、浏览画板、批注、对比、导出及通信校验的通用代码随插件统一交付；项目保存具体原型 HTML、页内契约、业务 CSS／JS、需求与设计规范。不在业务仓库反复投放通用查看器。业务样式不能因插件更新被替换。
- **REQ-202：离线评审快照。** prepare 使用当前物理插件中的已核对资源，按当前项目与 request 生成用户级私有、不可变的本轮评审包，含通用工具和明确页面的必要依赖快照；不复制整个项目，不要求 HTTP 常驻服务、MCP、项目登记或旧中央运行时。页面仍以项目源文件为编辑权威。
- **REQ-203：版本与反馈绑定。** 本轮评审固定工具版本／内容摘要、需求字节与原型依赖指纹；插件升级不覆盖正在打开的评审包。反馈回传重读项目当前源校验，旧来源、工具不匹配、未知字段、越界与损坏明确拒绝，不自动重绑或静默采用 latest。
- **REQ-204：页面与浏览。** 新原型不依赖项目中的通用查看器文件，保留离线直接打开及完整页内契约；查看器从明确选定页面与来源元数据生成导航，不新增第二份业务 spec／页面渲染 JSON。旧项目目录中的具体页面、业务组件和原分组语义保留。
- **REQ-205：有界迁移。** 迁移必须先只读预览归属与影响，再按同一来源快照执行；只清理有充分依据的通用旧壳，不按 index/prototype.css/prototype.js 文件名批量删除。混合业务样式、用户修改、来源不明和活动使用冲突保留并报告；失败可恢复，不破坏唯一业务资料。原型格式迁移不恢复 2.0 运行时兼容。
- **REQ-206：三端插件消费。** 三个平台携带同一工具核心、模板与白名单入口，按实际项目目录和同一 adapter 打开。工作流与设计／验证说明同步到新归属，避免下一次设计继续复制旧壳；配置服务和真实模型偏好不在此次改动范围。
- **REQ-207：验证与交付。** 核心验证快照稳定、版本更新、反馈失效、路径／符号链接保护、并发、失败恢复及归属预览。Web 验证使用现有查看器视觉与控件合同，采用冻结 alpha.7 模板为零设计差异的生产基线，检验真实离线通信、批注、导出与载入。打包验证真实包外消费；集成使用唯一独立 QA，不增原型 QA 或新业务确认。

## 方案与原型关联

沿用现有 CSS 语义值、页面布局和控件语义。生产模板由 Web 实施角色维护，反馈在外壳中渐进展开；当时实现不修改受保护的既有设计样稿，也不把设计变更标成非 UI。原有样稿仅保留其未受影响范围，不能冒充节点反馈新增能力已获视觉批准。

核心采用只读 `prepare`／`validate`：根据显式项目适配器及需求 Markdown 调用既有原型校验器，准备一个含有限评审上下文的 `file://` 工作区链接；浏览器收集输入后导出反馈，核心重算真实来源并生成给 UI Agent 的节点修改交接。由 UI Agent 在既有 owned_paths 下修改原 HTML、重跑原校验，再由 PM 按原规则处理需求变化或视觉批准。本轮无需新 CAS 或任务图状态机制。

评审上下文只携带 schema、request_id、adapter、prototype_root、plan_source、plan_sha256、需求标签和逐页 path／dependency_fingerprint。最多 16 页，解码正文最多 8 KiB，fragment 最多 12 KiB。链接只允许唯一的 page／review 参数；换页保留 review。它不是权限凭证，不携带布局树、HTML 或批准字段。父子通信仍核对真实 source、origin、当前页及本轮随机 token；父壳不遍历 file:// 子页 DOM。

反馈格式使用封闭 schema 1：context 加 items；条目包含稳定反馈 id、page、target_id、kind、message、req_ids，可附当前文字／建议文字的 comparison、interaction_id 和 interface_refs。条目 ID 唯一，同一节点可以有多条独立意见。所有文字与片段均当作不可执行输入，`approved` 等字样不产生批准。上下文损坏时保留普通浏览并停用本轮反馈；后台复核失败保留原意见，禁止自动重绑至新版本。

三条实施线分别维护：反馈核心与薄 CLI；生产模板 UI 及真实浏览器用例；工作流消费说明、打包及测试入口。协议先固定，文件所有权不重叠；采用同一工作树集成。PM 保存本计划、批准依据和当前恢复状态。现有 `prototype_workspace_runtime` 必须纳入当前原型验证入口。

### 插件工具与项目资产

prepare 从实际物理插件读取已核对通用资源，生成用户级私有、按工具内容固定的 schema 2 离线评审快照；只复制明确页面及必要依赖。项目源仍是编辑权威；后续插件更新不改既有快照。回传重读当前项目与需求来源，按工具身份与依赖指纹拒绝过期反馈。

配置工作台的第四版设计批准属于 [模型偏好主题](native-model-preferences.md)，不是通用查看器的视觉依据。查看器沿用冻结 alpha.7 的既有视觉与控件权威，只变更资源归属和加载机制；原型源页面及状态链接见第 5 节。

### 单一主题与已验收基线

同一稳定主题在所选项目 adapter 的 `docs.plans` 内维护一份可编辑 Markdown，原位承载需求、方案、原型关联、当前恢复入口、上一已验收行为及必要批准证据。Full 采用[计划模板](../../templates/docs/PLAN.md)的六节形状；批准前草稿可留在当前请求证据区，批准后首次派发前保存。Light 按实际恢复需要保存，不强加 Full 计划或 QA。

当前目标、阶段和恢复状态与已交付事实分开。PROJECT 仅维护当前概况和明确验收的主题基线链接；completed、勾选和文档存在不证明功能已交付。Full 等集成 QA PASS 后，由 PM 投影当前已验收事实；Light 等必要验证及实际选择的审查接收后再投影。失败、暂停和取消保留原基线，不新建 feature 或 ADR 形成第二权威。

业务项目中已有计划、原型、规范、批准与恢复证据按原归属保留；此前迁移归档的 notes 原件与恢复资料继续由原资料位置保管，本仓旧说明删除不代表删除业务原件，也不抬升或撤回任何业务验收。项目自有字节、权限和工作区改动按实际授权保护；协作按项目语言约定，代码编写与优化保留详细中文注释，内置指令语言不改变确认、角色权限、fresh/handoff 与 QA 语义。完整日志与唯一恢复资料留在请求证据区，Git 保存完整历史。必要经验归既有相关主题或适用规范；没有归属时留当前交接，不建立 notes、替代杂记目录、空索引或占位主题。

### Markdown 需求与原型 HTML

需求和计划只以 Markdown 编辑、评审、派发与验收，不再生成同名 HTML。原型设计、具体原型 HTML、静态验证、依赖指纹和适用视觉确认仍有效。用户需求确认先包含原型建议与选择，需要原型时，具体页面准备完成后再进行视觉确认；原型验证本身不新增业务确认。

设计 Agent 在所选 adapter 的 `docs.standards_root/prototype` 内交付交互页面，并在原交接中返回需求覆盖、规范符合性、交付一致性自检。PM 将稳定 REQ ID 与具体页面、实际状态锚点的关联写入同一 Markdown，不另建映射报告或独立原型 QA。批准绑定实际页与依赖指纹；公共依赖改变时仅重开受影响页面。

原型页通过 `body[data-prototype-plan-source]` 绑定配置 `docs.plans` 下的规范 Markdown 路径；唯一 `nav.prototype-requirement-links` 包含一个 Markdown 链接，独立打开并包含 `target="_blank"` 与 `rel="noopener"`。已有业务项目的同名历史 HTML 可作为可选安全导航，不作为当前编辑权威或渲染依赖。本仓库退役计划 HTML 的导航已移除，通用样稿关联本页 Markdown。

先保留明确已验收的项目基线与原始批准，再更新当前任务包及必要链接。用户明确“本次只改实际产品、不改原型”按本次范围落实，并说明旧原型对本次变更的适用边界；原型评审中的修改仍归原型，按已批准原型实现仍需读取有效依据。
