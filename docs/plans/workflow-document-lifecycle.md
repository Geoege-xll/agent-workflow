# 3.0 主题文档与原型评审工作区

- 主题 ID：`workflow-document-lifecycle`
- 阶段：`active`
- 模块：主题文档、原型模板、反馈输入与修订交接
- 任务等级：`Full`
- 已验收版本：`3.0.1`

## 目标与范围

提供单一主题 Markdown 生命周期、高保真原型评审与增量反馈，以及随插件维护的通用离线评审工具。当前正式基线3.0.1延续alpha.9的节点反馈与资源归属能力；本轮新增评审操作流重设计，旧交付和当前候选分开记录。

借鉴外部项目的稳定节点、结构化反馈和局部修改交接，保留两步确认、唯一独立 QA、需求 Markdown 权威及原生角色职责。通用工具由插件交付，项目只保存具体原型、业务 CSS／JS、需求和设计规范。三个业务项目实际迁移尚未执行。

不引入拖拽编辑、通用 JSON 页面渲染器、HTTP 常驻服务或模型 MCP；不恢复计划 HTML、TUI、旧中央运行时、npm／npx 或退役 2.x 直装兼容。Windows 暂停。

### 插件统一评审工具的已验收归属基线

以下REQ201—207保留既有插件资源归属与安全边界；其中当时的视觉／控件依据属于历史交付，不作为新版整改界面的批准。当前交互以REQ801—812为准。旧架构分析关于历史前后画面和Agent版本差异的方案已不采用，独立来源／不可变包校验继续保留。

- **REQ-201：资源归属。** 导航、浏览画板、批注、对比、导出及通信校验的通用代码随插件统一交付；项目保存具体原型 HTML、页内契约、业务 CSS／JS、需求与设计规范。不在业务仓库反复投放通用查看器。业务样式不能因插件更新被替换。
- **REQ-202：离线评审快照。** prepare 使用当前物理插件中的已核对资源，按当前项目与 request 生成用户级私有、不可变的本轮评审包，含通用工具和明确页面的必要依赖快照；不复制整个项目，不要求 HTTP 常驻服务、MCP、项目登记或旧中央运行时。页面仍以项目源文件为编辑权威。
- **REQ-203：版本与反馈绑定。** 本轮评审固定工具版本／内容摘要、需求字节与原型依赖指纹；插件升级不覆盖正在打开的评审包。反馈回传重读项目当前源校验，旧来源、工具不匹配、未知字段、越界与损坏明确拒绝，不自动重绑或静默采用 latest。
- **REQ-204：页面与浏览。** 新原型不依赖项目中的通用查看器文件，保留离线直接打开及完整页内契约；查看器从明确选定页面与来源元数据生成导航，不新增第二份业务 spec／页面渲染 JSON。旧项目目录中的具体页面、业务组件和原分组语义保留。
- **REQ-205：有界迁移。** 迁移必须先只读预览归属与影响，再按同一来源快照执行；只清理有充分依据的通用旧壳，不按 index/prototype.css/prototype.js 文件名批量删除。混合业务样式、用户修改、来源不明和活动使用冲突保留并报告；失败可恢复，不破坏唯一业务资料。原型格式迁移不恢复 2.0 运行时兼容。
- **REQ-206：三端插件消费。** 三个平台携带同一工具核心、模板与白名单入口，按实际项目目录和同一 adapter 打开。工作流与设计／验证说明同步到新归属，避免下一次设计继续复制旧壳；配置服务和真实模型偏好不在此次改动范围。
- **REQ-207：验证与交付。** 核心验证快照稳定、版本更新、反馈失效、路径／符号链接保护、并发、失败恢复及归属预览。Web 验证使用现有查看器视觉与控件合同，采用冻结 alpha.7 模板为零设计差异的生产基线，检验真实离线通信、批注、导出与载入。打包验证真实包外消费；集成使用唯一独立 QA，不增原型 QA 或新业务确认。

### 本轮批注评审融合

- **REQ-801：浏览与批注。** 浏览保留实际原型交互：下拉真实展开并可选、既有按钮／弹窗／页面跳转可体验，页面切换同步导航与视口／草稿。画布只在空白／空格／中键手势平移，不抢设计稿点击、输入及字段滚轮。已核示例通用默认原生select和导航有真实本地响应，逐Agent模型／推理旧按钮仅循环文字；本轮改为保留稳定ID和外观的本地演示select，不接真实目录或API。批注才捕获全部可见有意义元素／容器，显示轮廓、父层选择及“标记位置／添加整改”浮动工具条，不展示拼接长摘要。标记位置是可选步骤，不成为添加整改的前置条件。目录只作键盘后备，匿名演示定位不可冒充真实源验证。本轮不做组件拖拽、结构编辑或可视文案编辑引擎。
- **REQ-802：画布就地操作与整改弹窗。** 去掉画布上方占空间的页名、路径、模式说明和整块背景条；缩放、适应、显示整改／定位标记等紧凑控件直接浮在画布上，固定于视口而不随设计稿变换，不遮挡主要交互。选中后点“添加整改”打开唯一编辑弹窗，以范围、类型、意见和可选定位引用为主，摘录／建议文字按需展开；不提供意见等级或隐藏默认等级。用户已要求移除弹窗的“关联需求”手选和“演示目标”技术定位展示；真实目标、来源版本及已有结构化引用仍在内部保留。需求关联只采用明确可靠的业务映射，未映射就留空，不能把本工具REQ801—812自动当成示例稿件的业务需求，不在本轮新增猜测式自动提取器。用户实际反馈要求删掉“xy-uiux界面与交互设计 继承”等textContent拼接长摘要，以及“调用偏好／调用偏好页”整块重复目标摘要：浮条和弹窗主区域都不再展示、不留占位，父层用简短固定动作标签，目标绑定仍保留。新增仅填写内容和可选定位引用，不再提供之前／之后／内部位置选择；具体位置关系用正文表达。完成才记录并编号；取消、Esc或误关保留草稿，不创建空条目。右侧管理清单，不保留第二套长表单。
- **REQ-803：真实范围。** 节点整改由点选目标带入；画布右上固定“页面整改”无需选节点，可写整页风格、布局或新增模块要求；右栏底部“本轮整体意见”覆盖本轮多个页面。三入口共用一个弹窗，由入口固定范围，不要求重复选择三段范围。整页／整体不伪造节点，不提供未经要求的删除整页或项目操作；页级新增可用页面为范围描述位置。
- **REQ-804：整改清单。** 右栏按两类对象提供“整改／标记”Tab，独立计数，默认整改；不是旧“本轮改动／我的意见”双轨。整改完成后生成本轮跨页稳定01、02等编号，清单与画布同号同色、双向定位。条目含类型、所属页、目标、摘要和编辑／撤回，编辑复用弹窗并保留编号；筛选、撤回和导出不重编号。允许同目标多条，撤回只移除该条标记，其他整改保留；同目标删除与修改／新增并存时提示冲突，不擅自覆盖或替用户取舍。保留单次撤回恢复、范围按需筛选；不新增复杂状态面板。Tab切换不改选中目标或草稿，底部本轮整体意见／复制固定共用，交还包含两类数据；完成整改切回整改并内部定位，创建A只更新计数，不强制跳Tab，点击已有A可切标记并定位。
- **REQ-805：便捷交还。** 主动作“复制给Agent”使用同一状态生成可读摘要与唯一机器载荷；复制前明确已保存条数与未保存输入，支持保存并继续或取消保留。复制失败提供手动复制／下载，准确区分已复制、已请求下载和真实宿主收取；纯离线工具不能显示Agent已收到或自动开始实现。
- **REQ-806：单一架构与来源。** 父壳协调页面／模式／会话，单一状态拥有选择、定位标记、整改、引用、草稿及导出，右栏和画布只是其视图。子页桥独占实际DOM命中、高亮、摘录与定位，保持source/origin/page/token边界；Python独立校验，装配器保持不可变离线包。HTML是唯一设计稿，不维护完整第二spec。不再构建本轮Agent版本差异清单，但仍保留意见的真实来源版本绑定，避免换版错指。
- **REQ-807：协议与验证。** 新反馈envelope3用真实node/page/global目标判别联合；context2、manifest与启动数据版本独立保持。旧反馈2走原严格节点分支，不静默迁移／重绑旧快照或草稿；未知／危险／过期输入明确失败且保留。工作流Task Pack仍schema2。先交互原型确认，再实施协议和真实工具，完成跨file桥、键盘、窄屏、草稿与失败恢复、导出／回传负控和三端包外消费，使用唯一独立QA；不以原型模拟或构建代替实际验证。
- **REQ-808：整改三色与编号。** 三色仅表达用户待处理整改：修改黄、新增内容绿、删除建议红，均配文字类型，完成一条才产生彩色编号并与右栏对应。不表示Agent已完成修改，也不依赖历史差异或虚构A/B；移除旧版本改动清单／删除痕迹展示。绿色仅标明参照区域存在新增建议，不画伪精确插入线或将已有容器整体冒充新增；具体意图由正文及A引用表达，不生成position字段。删除建议不立即删除设计稿，清单“撤回”则移除该条及对应覆盖层。标记不占产品布局，可隐藏；整页整改通过右上入口和清单提示，不铺整页色块。多条标记错开，选中项突出。
- **REQ-809：固定评审工作台。** 插件提供通用本地工作台，项目提供实际HTML。顶层深色工具栏、默认收起的原型页面抽屉、中央完整设计稿与固定右栏保留；右栏使用整改／标记两个实体Tab，标记不再藏于折叠区。缩放不改变选定设计稿视口；切页恢复相机和草稿。原型页导航与稿件内部业务导航区分。去掉画布上方独立大块标题条，空间给画布；工具浮于画布。无连线、组件库、组件拖拽或另一套spec渲染器。

  最新右栏视觉要求：整改／标记Tab及计数作为唯一紧凑顶部区域，筛选按需展开为轻量同一行；整改编号、类型与完整意见为主，页面／短目标／引用为次，动作统一分组，以细分隔减少框中框和大块空白。标记Tab沿用同一尺度；主要文字保持13—14px可读，不靠整体缩字提高密度。底部单一固定操作带，本轮整体意见次要、复制主要，不额外叠统计行和长说明。重排对应DOM／renderer／样式职责，不叠无效覆盖规则或增加功能。

  用户明确工具页例外：工作台自身为顶层页面，不套通用标题、浅底、大边距或卡片框；开发契约改为大弹窗而非底部展开占画布。本页专属处理，不改公共原型样式或放宽验证器。
- **REQ-810：运行代码架构整理。** 用户明确要求整理工作台运行代码，不能以旧脚本不断追加分支。复用并梳理现有离线装配、受控页面导航、画布视口与定位、改动记录、唯一评审状态、编辑／列表视图、导出与独立校验边界。通用壳由插件维护，项目仅维护设计稿及业务资源；改动清单不成为第二份页面结构权威。不引入通用框架或常驻服务，保留现有来源绑定、不可变快照、草稿恢复、封闭验证及两步确认。当前按已采用的最终原型实施运行模块整理，完成必要验证与唯一独立QA。
- **REQ-811：独立定位标记。** 选中元素后“标记位置”生成中性A01、A02，与彩色整改01、02独立编号／计数。重复标记同一目标定位已有标记，不重复创建；多个整改可引用同一标记，一条可引用多个标记。弹窗可选择标记插入引用，右栏引用可定位；导出包含真实目标关联，不只自由文字。被引用标记保留并显示引用关系，解除引用或撤回相关整改后才可移除；可隐藏展示。编号本轮稳定不复用；换版失配保留原意见并报告，不自动重绑。

  编号移除入口必须可发现：点击已有A编号，在同一浮条提供“移除标记”，未被引用可立即移除；被完成项／草稿引用时显示原因和关联入口，不能无提示失效。点击彩色整改编号可就地“撤回整改”，复用清单撤回及单次恢复逻辑；只影响明确选中的那一条和对应覆盖层，不删除稿件或其他编号。不能只在右侧列表提供移除。
- **REQ-812：开发契约大弹窗。** `Page design and interaction contract`仍完整保留唯一五段和控件关联，通过紧凑“开发说明”入口打开大尺寸原生模态，内部滚动、关闭／Esc及回焦点明确，平时不占画布或底部纵向空间。可保留原details语义以供原验证器读取，但实际契约放在模态内，打开时直接可阅读，不要求再点第二次展开；不得复制成两份或修改验证器放宽门禁。演示边界、需求Markdown可归入该弹窗。
