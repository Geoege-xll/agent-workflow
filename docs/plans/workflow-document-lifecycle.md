# 3.0 主题文档与原型评审工作区

- 主题 ID：`workflow-document-lifecycle`
- 阶段：`active`
- 模块：主题文档、原型模板、反馈输入与修订交接
- 任务等级：`Full`
- 已验收版本：`unreleased-live5`

## 目标与范围

提供单一主题 Markdown 生命周期、高保真原型交付与独立评审工具。用户将 `docs/standards/prototype/` 称为“交付目录”，将修改协助工具称为“评审工作”。当前迭代采用两个独立网页、同一设计原稿和共用画布；正式安装基线仍为3.0.2，已验收但未发布的feedback4源码及其完整证据继续保留。

当前范围为交付查看入口、共享画布、独立评审页、唯一原稿读取与批注持久化。复用已确定的深色工具视觉；不再增加同页模式切换，不重新设计产品原型业务界面。用户明确“开始优化”并选择交付时启动服务，作为实施授权。当前源码已完成独立验收，使用`unreleased-live5`区分尚未正式发行和安装的源码基线；发行与本机事实归[发行主题](stable-product-release.md)。

借鉴外部项目的稳定节点、结构化反馈和局部修改交接，保留两步确认、唯一独立 QA、需求 Markdown 权威及原生角色职责。通用工具由插件交付，项目只保存具体原型、业务 CSS／JS、需求和设计规范。三个业务项目实际迁移尚未执行。

不引入拖拽编辑、通用 JSON 页面渲染器、模型 MCP、系统启动项或自定义系统URL协议；不恢复计划 HTML、TUI、旧中央运行时、npm／npx 或退役2.x直装兼容。Windows暂停。评审服务限定在本机、显式项目和登记资源闭包，独立于Native Agent Config。用户已明确选择插件在交付时准备并启动服务；完整目录、画布和一键评审使用本次具体页HTTP入口，磁盘HTML仍可离线查看业务演示和设计合同，但不承诺离线服务发现或冷启动，也不把凭据／机器路径写回原稿。

## 需求与验收

### 当前迭代：交付与评审分离

- **REQ-1001 交付查看。** 插件为每个具体原型提供独立HTTP查看入口，使用统一可缩放画布和默认收起的左悬浮页面目录；目录从实际页面元数据统一派生，不在每页手抄。磁盘HTML仍可独立离线查看原稿，不要求离线文件查找服务或复制整套工具。不再使用额外的项目导航index壳；只移除已确认归属的导航壳，不按文件名删除业务首页。保留原型真实交互及具体HTML中的五段设计与交互合同。
- **REQ-1002 独立评审。** 交付页提供“进入评审”，在新标签页准确打开当前页面。原交付页保持；评审工作进入即评审，无左悬浮目录、浏览／批注切换和开发说明，保留中央画布、浮动控件、整改／标记右栏、编辑弹窗、同号同色及交还。两个网页的相机和交互状态独立，不承诺任意内存状态同步。
- **REQ-1003 唯一原稿。** 交付与评审共用画布组件并读取交付目录的同一设计源；不提取innerHTML拼接第二份页面，不为活动评审在磁盘维护业务HTML副本。来源键和通信桥仅在服务响应中装配；意见、会话与版本元数据独立保存。原稿静态源及资源依赖仍由既有安全捕获和定位核心验证。
- **REQ-1004 精确边界。** 只评审实际设计内容，外壳目录、工具和设计合同不参与节点选择。弹窗、菜单及详情展开后可定位；采用临时操作手势进入目标状态，释放后继续批注，不恢复持久浏览模式。无来源动态节点明确提示选择真实源父层，不能静默改绑。
- **REQ-1005 持久化与变更。** 刷新和重新进入可恢复当前评审意见；并发保存冲突明确可见，不静默覆盖。意见绑定实际来源修订，源变化保留原意见并阻止错误定位和提交，明确要求重新核对；不能用“当前版本”指针重绑旧反馈。重复打开复用相应活动会话，不无条件累积原型副本。
- **REQ-1006 启动与安全。** 只允许可信CLI登记真实项目、adapter、需求和具体页；网页不接受任意文件根、shell参数、安装或执行请求。服务仅本机环回、严格Host／Origin／认证，设计内容与控制权限隔离；内容仅来自登记的安全资源闭包。服务不可用有准确恢复说明，不虚称静态按钮能够启动Python，不配置系统自启动。
- **REQ-1007 协议与架构。** 历史feedback2／3／4和不可变包仍按原闭合合同只读消费，新活跃源协议明确版本化。先冻结旧资产与装配语义，再新增来源／修订、服务生命周期、共享画布和交还适配；不将服务、权限、业务规则与页面DOM集中到单一脚本。三端插件携带相同核心及必要白名单资产，说明与生成模板同步。
- **REQ-1008 验收与保留。** 验证两页同源内容、共享相机、真实交互、新标签页当前页、弹窗后选择、编号／引用／撤回、草稿刷新、并发及原稿变化拒绝；以无业务HTML副本和源文件不被评审改写为验收条件。使用生产工具的最小真实浏览器与三端包外消费，唯一独立QA审查源码和有效证据。保留既有配置页修复、项目资料、历史反馈及原始失败；不批量迁移三个业务项目或删除其资料。

以下需求保留为既有基线；本轮承载、导航、预览和开发说明的冲突以REQ-1001—1008为准，旧版消费仍按各自历史协议。

### 精简反馈（已验收、未发布源码基线）

- **REQ-901：必要内容。** 复制和下载使用同一紧凑反馈，不再附带重复正文摘要、全量需求标签、全部页面／工具清单、自动大段当前文字摘录或来源可还原的REQ／交互／接口字段。保留整改稳定ID和编号、操作、准确目标、用户意见及明确填写的建议文字；不缩写成无法理解的字段。完整来源只存本地不可变评审快照，短引用不能作为权限或批准。
- **REQ-902：来源与容量。** 新feedback4使用短review引用，由显式项目／adapter和request_id／review_id在既有私有目录定位唯一快照，不扫描其他项目或请求。新context3只存真实REQ ID目录，完整需求仍在原Markdown；新manifest／boot／bridge各为4。保持8KiB上下文、1MiB反馈与256条目等现有边界，不能靠放大上限掩盖冗余。未知字段、危险路径、跨项目、缺包、过期源及损坏均明确拒绝，意见不丢失。
- **REQ-903：精简修订交接。** validate成功后返回短来源和按目标分组的整改，目标只出现一次；REQ／交互／接口关联从已重读的真实源按需投影，省略空的可选数据，不回传完整context。被引用A标记完整交给UI Agent，不只交reference_ids；未引用A保留工作台状态，普通整改交还可过滤；仅有标记时仍能交还这些明确标记，不猜测整改。
- **REQ-904：现有交互保持。** 沿用已验收顶层深色工作台和唯一交还弹窗，复制、手动备用及下载同一数据；交还计数对应实际复制内容。页面／整体／节点范围、编号、引用保护、草稿、撤回恢复、来源变化拒绝、失败反馈及键盘行为保持。没有新视觉决策，不改原型、样式规范或布局，不增完整版／精简版切换。
- **REQ-905：版本与架构。** 已生成3.x的feedback2／3、context2和对应不可变包按原格式严格只读复核，旧草稿不迁移；新增格式只由当前工具生成。协议与投影、快照读取／装配、状态与浏览器呈现分别归既有职责，必要拆分纯合同，不新增服务、MCP、项目伴随文件或第二份页面权威。不修改第三方vendor、2.x安装兼容和Native Agent Config；Codex列表排查为另一个只读请求。
- **REQ-906：验收。** 用当前长需求Markdown真实prepare与严格validate证明不再因长标签超限；验证跨页A、仅标记、匿名源目标、节点／页／整体、建议文字、来源变化及缺包／损坏／越界负控。生产模板的真实file浏览器复制／失败备用／下载结果交给同一Python入口，比较等价意见的UTF-8字节而不伪称token节省；三平台包外消费及唯一独立QA覆盖当前源码与必要标准。原失败、旧包和原始导出证据保留。

### 插件统一评审工具的已验收归属基线

以下REQ201—207保留既有插件资源归属与安全边界；其中当时的视觉／控件依据属于历史交付，不作为新版整改界面的批准。当前交互以REQ801—812为准。旧架构分析关于历史前后画面和Agent版本差异的方案已不采用，独立来源／不可变包校验继续保留。

- **REQ-201：资源归属。** 导航、浏览画板、批注、对比、导出及通信校验的通用代码随插件统一交付；项目保存具体原型 HTML、页内契约、业务 CSS／JS、需求与设计规范。不在业务仓库反复投放通用查看器。业务样式不能因插件更新被替换。
- **REQ-202：离线评审快照。** prepare 使用当前物理插件中的已核对资源，按当前项目与 request 生成用户级私有、不可变的本轮评审包，含通用工具和明确页面的必要依赖快照；不复制整个项目，不要求 HTTP 常驻服务、MCP、项目登记或旧中央运行时。页面仍以项目源文件为编辑权威。
- **REQ-203：版本与反馈绑定。** 本轮评审固定工具版本／内容摘要、需求字节与原型依赖指纹；插件升级不覆盖正在打开的评审包。反馈回传重读项目当前源校验，旧来源、工具不匹配、未知字段、越界与损坏明确拒绝，不自动重绑或静默采用 latest。
- **REQ-204：页面与浏览。** 新原型不依赖项目中的通用查看器文件，保留离线直接打开及完整页内契约；查看器从明确选定页面与来源元数据生成导航，不新增第二份业务 spec／页面渲染 JSON。旧项目目录中的具体页面、业务组件和原分组语义保留。
- **REQ-205：有界迁移。** 迁移必须先只读预览归属与影响，再按同一来源快照执行；只清理有充分依据的通用旧壳，不按 index/prototype.css/prototype.js 文件名批量删除。混合业务样式、用户修改、来源不明和活动使用冲突保留并报告；失败可恢复，不破坏唯一业务资料。原型格式迁移不恢复 2.0 运行时兼容。
- **REQ-206：三端插件消费。** 三个平台携带同一工具核心、模板与白名单入口，按实际项目目录和同一 adapter 打开。工作流与设计／验证说明同步到新归属，避免下一次设计继续复制旧壳；配置服务和真实模型偏好不在此次改动范围。
- **REQ-207：验证与交付。** 核心验证快照稳定、版本更新、反馈失效、路径／符号链接保护、并发、失败恢复及归属预览。Web 验证使用现有查看器视觉与控件合同，采用冻结 alpha.7 模板为零设计差异的生产基线，检验真实离线通信、批注、导出与载入。打包验证真实包外消费；集成使用唯一独立 QA，不增原型 QA 或新业务确认。

### 本轮批注评审融合

- **REQ-801：浏览与批注。** 浏览保留实际原型交互：下拉真实展开并可选、既有按钮／弹窗／页面跳转可体验，页面切换同步导航与视口／草稿。画布只在空白／空格／中键手势平移，不抢设计稿点击、输入及字段滚轮。已核示例通用默认原生select和导航有真实本地响应，逐Agent模型／推理旧按钮仅循环文字；本轮改为保留稳定ID和外观的本地演示select，不接真实目录或API。批注才捕获全部可见有意义元素／容器，显示轮廓、父层选择及“标记位置／添加整改”浮动工具条，不展示拼接长摘要。标记位置是可选步骤，不成为添加整改的前置条件。目录只作键盘后备，匿名演示定位不可冒充真实源验证。本轮不做组件拖拽、结构编辑或可视文案编辑引擎。
- **REQ-802：画布就地操作与整改弹窗。** 去掉画布上方占空间的页名、路径、模式说明和整块背景条；缩放、适应、显示整改／定位标记等紧凑控件直接浮在画布上，固定于视口而不随设计稿变换，不遮挡主要交互。选中后点“添加整改”打开唯一编辑弹窗，以范围、类型、意见和可选定位引用为主，摘录／建议文字按需展开；不提供意见等级或隐藏默认等级。用户已要求移除弹窗的“关联需求”手选和“演示目标”技术定位展示；真实目标、来源版本及已有结构化引用仍在内部保留。需求关联只采用明确可靠的业务映射，未映射就留空，不能把本工具REQ801—812自动当成示例稿件的业务需求，不在本轮新增猜测式自动提取器。用户实际反馈要求删掉“xy-uiux界面与交互设计 继承”等textContent拼接长摘要，以及“调用偏好／调用偏好页”整块重复目标摘要：浮条和弹窗主区域都不再展示、不留占位，父层用简短固定动作标签，目标绑定仍保留。新增仅填写内容和可选定位引用，不再提供之前／之后／内部位置选择；具体位置关系用正文表达。完成才记录并编号；取消、Esc或误关保留草稿，不创建空条目。右侧管理清单，不保留第二套长表单。
- **REQ-803：真实范围。** 节点整改由点选目标带入；画布右上固定“页面整改”无需选节点，可写整页风格、布局或新增模块要求；右栏底部“本轮整体意见”覆盖本轮多个页面。三入口共用一个弹窗，由入口固定范围，不要求重复选择三段范围。整页／整体不伪造节点，不提供未经要求的删除整页或项目操作；页级新增可用页面为范围描述位置。
