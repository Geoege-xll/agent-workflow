# 通用规范单一来源与设计自检补齐

用户明确选择原型阶段继续由设计 Agent 自检，按需求覆盖、规范符合性、交付一致性
检查，保留用户最终确认，减少流程环节；随后要求一并补齐通用规范迁入内置 Skill、
项目仅维护特有规范和有实际内容的薄索引，以及安装、来源解析、指纹、QA 覆盖迁移。
本计划落实这些已明确决定，不重复请求同一范围的确认。

本轮属于源包 Full／non_ui 变更。需求覆盖充分，没有待决产品或原型选择。
保留 a2356dd 的技能升级和 2dbe675 的任务分级、实施所有权与恢复边界。
PM 只维护计划、合同、调度、证据接收与收口；三条实施线负责源码、指令及测试，
最后由原独立 QA 统一审查。本轮不修改、安装或同步三个业务项目，也不推送远程。

## 方案与边界

- `xy-code-standards/references/rules.md` 成为通用工程规则正文来源；原 GENERAL 的
  三十条共通规则、验证和秘密管理规则，以及仍适用的通用上游保护规则完整迁入。
  `xy-ui-design/references/foundations-rules.md`、`components-rules.md` 承接两设计模板
  的通用规则。保留稳定 ID、hard/advisory、领域和条件适用语义，不复制项目品牌、
  暖色、材质、具体尺度或业务偏好。
- 项目规范叶只保存技术栈、业务、平台、品牌和已批准的特殊要求。索引只链接这些叶。
  无项目规范时不生成空索引或占位叶；已有自定义索引、无标记文件和项目独有内容保护。
  旧 GENERAL 仅清理能证明归属的通用内容，区外项目字节保留；修改或归属不明确时
  停止相应删除，不能按文件名猜测所有权。索引更新只修补实际迁移产生的链接变化。
- 规则来源解析、任务初始化、指纹和 QA 覆盖沿用现有合同，精确识别内置规则路径与
  项目浅层叶；缺失项目索引不等于缺少通用规则。保留领域、设计写入、保护路径、
  规则覆盖和证据过期检查，不允许用任意 Markdown 冒充内置来源。
- 设计 Agent 三维自检融入既有原型验证和交接，用户确认与后续功能独立 QA 保留。
  不新增原型 QA、报告、审批、默认浏览器、截图或第二设计权威；后续 QA 复用有效
  设计结论，仅检查实际实现及变化影响。跳过原型、UI-Conformance 和 standards_only
  的适用边界保持。

## 实施与接口

1. 内容线迁移规则正文，更新 Skill、角色、流程、薄索引模板和当前公开说明；旧模板
   删除前由全部实施者独立读完旧规范，迁移依据可从本轮已提交基线恢复。
2. 运行时线调整现有规则来源分类、文档校验、任务图及 QA 覆盖消费者；规范源仍进入
   原 leaves 和逐规则审查，项目叶的路径边界不扩大。与内容线冻结精确新源路径。
3. 安装线复用一个规范迁移计划，供共享脚手架、AGY 发布器与总安装回滚使用；覆盖
   精确删除、幂等、权限、并发变更和失败恢复。三线单路径单 Writer，接口差异由 PM
   收敛后替换受影响完整任务包，不能接受旧合同的完成结果。
4. 唯一独立 QA 审查完整当前差异、规范保真、真实安装与运行证据，以及最小情境
   应用。修复仅回原作者，同一 QA 差量复查；三轮失败沿既定路线升级。
