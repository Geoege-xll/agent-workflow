## 统一方案

- 仅保留 Light／Full。Light 的实现默认派对应原生 subagent，按当前目标先判断风险、
  范围和实施者，保留最小充分验证；交接时评估独立审计、文档与记忆，不强制 Full
  规划、DAG、保存计划或独立 QA。Full 保留既定规划、适用确认与独立 QA。普通开始
  指令不授权 PM 亲自实施；PM 仍只维护计划、交接、协调和已验收文档投影。
- 别名稳定绑定项目内模块根与规范角色，允许同模块多个独立槽位，但一条路径一个
  Writer。独立任务使用新原生 ID；同任务连续实现及短期返工可以续用，同一轮 QA
  仍由原 Reviewer 差量复查。旧身份、FAIL、批准和完成证据不能被换绑或跨任务挪用。
- 新实例只接收当前自包含任务包，不继承或复制完整 PM／兄弟会话，不使用会复制
  父历史的 fork。交接包含目标与精确范围、当前代码和工作区依据、适用规范、可信
  授权来源、验收与必要证据、未解决事项；当前文件和必需规范仍由接收方核对并读取。
  声明字段或文件指纹不等于原生隔离已实测，也不能证明模型已经阅读。
- PM 接收交付、必要验证／QA 完成且成果与证据安全后，使用当前实际暴露并获授权的
  原生结束能力。能力缺失或失败只退役并阻止自动复用，记录原生结束未确认；不伪称
  清空内存、不默认永久删除历史。AGY 的临时 worktree 及唯一日志必须先保护。退役
  本身不能释放仍在执行的任务锁；取消、失效和未知状态继续由 PM 核实恢复。
- 借鉴有限复用池的职责分组、按需创建及适时回收，不预创建全部别名实例、不为填满
  容量而保活。平台运行中／打开线程上限按实际宿主口径观察，不假定等于缓存池容量。
  实例围绕当前独立交付单元的反馈窗口保留，近期实现返工及同轮 Reviewer 优先续用；
  闭环后及时回收。容量不足先回收已验收且交接充分的实例，不能用简单 LRU 淘汰
  正在执行、证据未交付或必要复查实例；派发时为后续必要 QA／集成安排容量。
  同名别名的新独立任务仍使用新原生 ID 与新上下文，不声称 resume／compact 已重置。

## 2.0 接口与实施所有权

运行时接口采用 schema_version: 2；任务包含 workflow_level（Light／Full）、module
（规范化项目相对模块根，根模块为 .）、规范 role、agent_alias、instance_policy: fresh、
context_policy: handoff_only。原生 agent_ref 仍为 host／agent_id，派发后首次绑定且不可
覆盖或清空；同图不同任务不得复用同一原生身份。agent_retired 是原任务上的不可逆
终止元数据，不构建 Agent 池或第二生命周期状态机，也不冒充宿主存活状态。

自包含交接外壳统一为 schema_version 与 task、当前适用 standards_contract 及必要
批准／UI 依据；只导出指定任务，不复制兄弟任务。Light 单包无需图；Full 沿用现有
task 图出口。QA 结果绑定实际当前 QA 包的请求、任务、别名、原生身份和字节 SHA，
validate／extract 接收当前 task-pack，不允许旧 PASS 冒充新交接的结果。

## 验证与验收

复用现有测试文件，补足真正的行为缺口：旧格式拒绝；Light 单包可校验且不要求图；
Full 门禁仍有效；导出仅含本任务与必要依据；父／兄弟历史及非法上下文政策拒绝；
同别名模块／角色不漂移、模块越界拒绝、跨任务同 ID 拒绝、历史身份不可覆盖；
同任务返工可续用，取消／未知／退役不得自动续用；退役不解锁仍活动 Writer，完成
任务不复活；当前 QA 包与结果身份／SHA 不符时拒绝旧 PASS。

三宿主生成、入口、能力诊断与真实临时项目安装／检查证明资源按 2.0 分发。针对受
影响消费者运行最小充分用例；解释型程序使用实际 CLI／安装消费者验证，不用静态
字符串检查冒充程序可运行。保留原命令、退出码和完整日志，独立 QA 核对当前输入后
复用有效结果，只为实际变化或未覆盖风险补验，不在每次交接和收口重跑保险回归。

不调用模型做三宿主服从性实验，不宣称实际销毁、缓存命中、token／费用或幻觉率
改善已经实测。原生能力缺口必须如实记录，特别是本会话没有 close／kill 工具。
本仓公开工作流说明随实现更新；没有业务 PROJECT／feature 事实需要投影，不复制
当前规则到记忆。完整必要证据使用本请求的单一 scratch，不按轮次复制源码或产物。
