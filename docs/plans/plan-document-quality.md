# 计划文档组织与有界校验

- 主题 ID：`plan-document-quality`
- 阶段：`completed`
- 模块：`platforms/shared/skills`、`lib/documents`、`templates/docs`
- 任务等级：`Full`
- 已验收版本：`local-pool-docs-c71fd883`

## 目标与范围

让首次接手的人能找到当前规则、代码入口和验收边界。PM 维护主题事实，开发和 QA 按当前任务读取相关章节。适用于已有计划、项目目录、规范及按需创建的架构文档。

## 需求与验收

### 主题的写作与验收

- REQ-401：保留稳定主题 ID 等现有元信息和历史六节。新稿按读者所需安排章节，可把已交付行为前置。已验收版本仍需批准依据与验收证据。
- REQ-402：借鉴分节组织、局部精修、去重一致性和读者问题检查；复用已知需求，不照搬上游多轮确认、占位输出或额外读者子代理。
- REQ-403：PM 更新原主题并替换失效内容。已验收基线与当前执行状态独立，完整日志和历史通过可恢复引用保存。
- REQ-404：新增 `validate_project_docs.py --root PROJECT_ROOT --plan PLAN`，`--plan` 可重复；不要求 PROJECT 已存在，不扫描未选择计划，不访问网络。原两位置参数入口和历史识别规则保持。
- REQ-405：显式选择的受管计划缺少必要字段及正文、元信息冲突、章节歧义、危险路径或坏本地链接时明确失败；代码围栏中的示例不充当元信息或章节。自然语言中的业务冲突由读者判断。
- REQ-406：三份现有主题与本计划通过同一指定文件校验；唯一 QA 验源、回归和读者可理解性，验证工作流确认／权限边界不变。

### 主题归属与引用

- REQ-407：指定计划校验拒绝同一主题 ID 的两份来源。提供编辑或新建前定位既有主题的有界入口，沿用实际 plans 路径和现有主题 ID，按需读元信息并原地更新；旧有显式指定文件的默认校验仍只读选中内容。
- REQ-408：PROJECT 的已验收基线索引不能重复列出同一来源。同一来源在说明区被有意义地引用仍可保留，历史未索引资料照旧保存。
- REQ-409：当前原型评审只消费明确的当前需求，历史章节继续可读。用[工作流文档生命周期](workflow-document-lifecycle.md)的真实混合文档验证当前目录范围，并复验已有评审快照的读取和来源校验。
- REQ-410：PROJECT 按主题导航，STANDARDS 按适用工作导航。进行中主题可收录；验收声明必须有证据。既有主题原位修改，单纯执行和符合性修复沿用本请求的可恢复交接。
- REQ-411：正文用有含义的相对链接标明依据、规范或具体交付物。按需查询显式引用可以定位源文件，区分导航和正文关系。查询结果是核查入口。
- REQ-412：用 mt-shop 的真实登录主题做四份范围明确的样稿，验证首次定位、UI 修复的文档去向和共用规范的引用反查。项目知识由 Markdown 目录、标题与相对链接维护。

### 标题导航与架构

- REQ-413：所有项目 Markdown 按标题组织。PM 和接单 Agent 可以先看直接子标题，再按完整标题路径只读目标正文。确需了解整个分支时可显式展开。
- REQ-414：正文提到其他文档时提供有含义的相对链接，指向具体章节时校验锚点。PM 检查本次改动的来源，文档移动或标题变更时复查受影响的引用。
- REQ-415：由 PM 在项目目录中提供一个代码架构入口，分模块维护职责、关键入口、调用与验证路径。用 mt-shop 普通用户微信登录作试点，验证首次定位能区分用户端和门店端。

### 从使用场景到原型与验收

- REQ-416：涉及业务行为的主题用当前读者能验证的场景表达角色、触发条件、反馈和适用的异常恢复。取舍、用户已确认的决定及实际测试结果各有明确依据。简短修复只保留实际需要的内容。[手机号登录示例](../usage.md#同一份需求怎样维护)
- REQ-417：主题可直接指向实际页面状态；页面上已声明的需求来源可直接定位到 Markdown 规则章节。校验明确给出的两端，保留整页导航和设计先行场景。PM 在原主题修订，设计 Agent 维护具体页面，验收可从任一端找到已确认的行为。[上游 PRD 与设计关联](https://github.com/mileson/open-vibecoding/blob/0468ec937386e0fdccb093c8a81bf50f63fb4a57/skills/open-vibecoding-prd/SKILL.md)

## 方案与原型关联

[写作规范](../../platforms/shared/skills/xy-plan/references/document-quality.md)约定主题的结构；[PM 生命周期](../../platforms/shared/skills/xy-workflow/references/plan-lifecycle.md)约定何时写入。只调整登录页间距以符合既有规范时，验证结果归本次交接。改变登录规则时，PM 修改已有主题。模块入口实际移动时，同步架构章节和受影响的引用。独立主题需要单独维护时再增页，并从目录链接一次。

需求确认、适用的原型视觉确认、独立验收和 PM 收口沿用[工作流定义](../../product/WORKFLOW.md)。分节写作参考 [Anthropic doc-coauthoring](https://github.com/anthropics/skills/blob/00756142ab04c82a447693cf373c4e0c554d1005/skills/doc-coauthoring/SKILL.md)。

- 本地已验收的目录支持进行中主题。目录引用和正文引用可分别反查，已验收声明须有批准及证据。共用规范变更、业务行为变更和符合性修复分别写回相应位置。
