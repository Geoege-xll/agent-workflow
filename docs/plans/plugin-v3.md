# 3.0 官方插件与原生 Agent 配置

- 主题 ID：`PLAN-PLUGIN-V3`。
- 阶段：当前 alpha 插件已完成本机三端安装，源码整理与交付收口进行中；不是公开市场稳定发行。
- 工作流版本源：`product/PLUGIN_VERSION`，`3.0.0-alpha.4`。
- 独立配置版本源：`native_config/VERSION`，`0.1.0-alpha.3`，已发布独立预发行资产。
- Windows 暂停；App GUI 未验；活动任务跨插件更新的自动资源保留协议未实现。

## 目标与范围

使用 Codex、Claude Code、Antigravity 官方插件机制分发工作流。独立配置工具按平台原生 Agent 身份发现用户级、项目级与插件来源，不限工作流固定角色；两个产品独立版本和打包，普通工作流不以配置组件、HTTP、网页或 MCP 为前置。

本仓当前资料收敛到 3.0：删除中央运行时、TUI、旧安装/同步、Homebrew/npm 历史指南及专用 HTML 原型。历史代码与执行证据在 Git 和原请求证据区追溯；此整理不批量改写业务项目、用户配置或其他用户安装。有效确认、调度、原型、独立 QA、文档和 notes 归属要求归入[使用手册](../usage.md)与[主题文档/原型指南](workflow-document-lifecycle.md)。

## 需求与验收

| 需求 | 当前合同 |
| --- | --- |
| 官方插件 | 三宿主清单、发现入口、精确资源与必要 helper 通过对应官方机制加载；不写全局指令或 trust 记录替代客户端权限 |
| 工作流保持 | Full 需求确认及适用视觉确认、Light 已有授权、用户明确直接开发、原型设计/HTML/静态验证、唯一独立只读 QA 与原收口顺序保留 |
| 持续接单 | PM 根据请求重叠、依赖、真实容量选择并行、复用、追加或等待；新生产任务 fresh/handoff_only，返工与原 Reviewer 增量复查按原实例承接 |
| 项目边界 | 项目 adapter 与插件权威分离；inspect 只读，明确 apply 仅建缺失 `.awf/project.yaml`；混用旧绑定拒绝，不伪造批准 |
| 独立配置 | 同一原生核心供网页/HTTP/脚本/可选 MCP；安全预览与保存、同名来源并列、插件缓存只读、实际继承与宿主字段边界保留 |
| 模型配置入口 | 显式 agent-config 仅进入固定维护路径；首次组件准备先确认并核验真实发行，不建业务图、不派代理，不阻断普通业务 |
| 交付事实 | 构建、安装、原生运行、独立预发行、公开市场稳定发行分别记录；真实失败与未验证项不改写为通过 |

准入 claim 只代表预留，创建未知不能释放重派；不同请求不共享批准或独立 QA 身份。配置保存与源码 SHA 不证明当前宿主已加载，也不证明新模型或推理参数实际执行。

## 方案与原型关联

工作流权威归 `product/`、`roles/` 和 `platforms/shared/skills/`；插件白名单装配与精确资源入口归 `plugins/`、`packaging/build_plugin.py`。独立配置核心归 `native_config/`，其构建与发行描述由独立构建器负责，不导入工作流角色枚举或旧管理器。

计划以 Markdown 维护，计划 HTML 生成链已退役；具体原型 HTML、通用分组工作区、安全导航、需求到页面状态关联、五节契约、依赖指纹和视觉确认保留。通用[工作区样稿](../standards/prototype/prototype-workspace.html)关联[当前指南](workflow-document-lifecycle.md)，TUI 专用样稿退出当前资料。

## 当前进展与恢复入口

当前精确本机候选已完成 Codex、Claude、Antigravity 的本地安装。Codex CLI 新插件实际启动通过；Claude 插件发现通过，默认模型在 90 秒预算内未回应，PM 实际接管未验；AGY 安装通过，模型运行待登录；App GUI 未验。较早 alpha.3 的单项 PM/派发/持续接单/模型实验及失败保留在[原生验收记录](plugin-v3-native-acceptance.md)，不当作当前所有客户端的复验。

独立配置 `0.1.0-alpha.3` 已预发行，真实资产校验、固定组件描述与维护路由阶段记录见[模型配置入口](agent-config-entry.md)。网页配置能力见[独立配置说明](../agent-configuration.md)；插件缓存仍只读，平台支持字段及统一默认设置边界不能扩大。

更新插件前先收尾或交接活动任务。后续需要继续验收 Claude 默认 PM、AGY 登录后的模型运行和 App GUI，不能从安装成功补写运行结论。文档清理与首页更新不引入新产品功能或重新开启旧渠道开发。

## 验收结果与当前已交付行为

已有源码与候选门禁记录按实际提交和原始证据保留，不因文档重组重复完整回归。当前验证入口为 `bash scripts/test_workflow.sh current`，覆盖两个产品、原型与候选交付；历史套件名称不等于当前产品状态。具体开发、构建和针对性验证方法见[开发手册](../development.md)。

原生验收已定位并修复 Codex portable 清单漏载 Hook、AGY Skill 超限截断和长文续读提示问题；修复不删共用权威正文或绕过官方信任。源码 QA、候选构建、精确安装与模型行为分别成立，包仍从 `runtime_verified:false` 开始。

独立组件预发行不代表插件稳定发行，当前公开市场尚未就绪。Git 合并、推送及主页更新以实际交付收据为准，不从本页阶段字段推断尚未完成的动作。

## 批准依据与必要证据

用户采用全新 3.0 插件体系，明确要求清理旧 2.0 文档、保留工作流运行要求，并继续合并 main、推送 GitHub 和更新主页。当前清理只覆盖授权的仓库资料；不自动重做业务项目迁移、不把早期旧文档当作当前操作批准。

阶段源码、CI、包摘要和原生失败/恢复的原始证据分别沿既有请求资料保留；核心原生记录见[验收记录](plugin-v3-native-acceptance.md)，独立组件发行与前向记录见[模型配置入口](agent-config-entry.md)。本次文档增量由同一请求的唯一独立 Reviewer 检查有效需求保留、引用闭包与当前状态边界。
