## 范围与设计

- 新增 `xy-code-standards`：短入口、按需边界推理参考及维护者来源参考。提炼三个项目的
  合同保真、语义复用、状态所有权和失败结果判断方法；项目 GENERAL 的稳定规则及读取合同
  继续权威，不复制三十条规范、不固定语言／框架，也不新增 TDD、审查、提交或发布阶段。
- 新增 `xy-ui-design`：短入口、设计质量和原型画布两份阶段参考。从 ParentsKit 提炼
  信息层级、产品 Token、共享组件和可演示交互，明确最终高保真交付要求。项目品牌、业务、
  具体数值和采用范围留在项目规范；满意原型不等于全部行为已合规。
- 从角色正文迁移重复专业方法，保留永久职责、精确写入边界、模式、平台约束、权限和交接。
  生产实施角色固定绑定代码技能；生产 UI 按任务读取设计技能；UI 角色绑定设计技能及既有
  设计／验证技能；QA 保留 `xy-qa-review` 固定入口并按审查面只读消费共用规则。
- 同步三宿主的现有清单、生成和校验。Codex 使用原有指令别名，Claude／AGY 使用各自
  真实绑定方式，不假定字段相同。预载不授予写入或触发阶段；Trivial、standards_only、
  UI-Conformance、用户选择直接开发和原型确认边界均保留。
- 旧七技能安装必须可证明归属后升级到九技能；当前生成物及检查只接受新合同。
  同名自定义、未知资源、原生信任、权限、模型及用户配置继续受到原保护。

## 研究依据与适用边界

UI 研究沿 ParentsKit 的 STANDARDS 索引解析设计基础、组件、颜色权威和现有原型，
仅提炼方法；发现的间距口径和反馈／收藏差异不能成为通用目标。代码抽查包含 mt-shop
协议正文与调用合同、ParentsKit 网络身份／写入重放边界、TeachingAssistant 文件发布
失败行为及对应测试。三个业务项目只读，本轮不修复其业务代码或规范。

开源参考采用 Anthropic frontend-design、UI UX Pro Max、社区 Karpathy guidelines 和
Vercel React Skill 中适用的方法，保留准确来源／许可与未采用内容；独立编写中文指令，
不引入外部截图、构建、CDN、第二规范权威或调度流程。详细来源保留在技能参考中。

1. 代码线独占新代码 Skill 的三个文件及五个生产实施角色 Markdown。

   失败只派回受影响实现者，同一 QA 检查差量；沿用原返工和停止规则。

## 验证与停止条件

验证技能入口／引用完整性、角色真实绑定、三宿主完整字节分发、旧受管安装升级与未知资源
拒绝覆盖，以及新技能引用损坏被检查拒绝。复用已有任务等级、UI 分支、原型画布和唯一
QA 合同覆盖；未改业务原型不重验 ParentsKit，不运行三个业务项目的全量测试。

以真实生成／安装消费者证明解释型生成逻辑可运行，按实际缺口选择现有定向用例。
两处既有 QA 分支测试在基线已使用过时标题／措辞；集成线在原测试文件中适配真实
分支定位，保留原早退与实施 QA 约束，不改变源规则来迁就测试，原始失败证据保留。
官方 quick_validate 若依赖不可用则保留真实限制，使用已有解析／生成校验，不安装全局依赖。
独立 QA 进行当前上下文内的实际任务推演，明确其不是三宿主模型普遍服从的实测。
必需验证充分且输入未变即停止，不在交接、QA 和收口各重跑一遍。

比较固定基线的角色常驻正文及各分支必读资源体积；字节／字符不冒充真实 token 用量。
