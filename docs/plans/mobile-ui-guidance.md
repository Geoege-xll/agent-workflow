# 通用 UI 质量与移动端开发规范

- 主题 ID：`mobile-ui-guidance`
- 阶段：`completed`
- 模块：共享 Skill、设计与开发及 QA 的角色接线、三端插件装配
- 任务等级：`Full`
- 已验收版本：`3.0.7`

## 目标与范围

强化 Web、桌面、原生 App 和小程序共用的设计一致性与关键流程恢复。3.x 插件提供按需加载的 `xy-mobile-ui`，覆盖 iOS、iPadOS、Android 和微信小程序的安全区与键盘、导航与返回、状态生命周期和无障碍。使用现有高保真 HTML 交付契约和 QA 交接。当前工作变更规则和技能分发，不涉及实际产品页面或新增原型。

## 需求与验收

- REQ-001：共享移动端规范只维护一份，写明适用条件、设计标注、实现与验收动作。通过带固定提交栏的表单和带底部导航的列表检查设计、实现与 QA 能使用同一份契约。
- REQ-002：Apple、Android 和微信小程序按实际技术栈、SDK 与运行版本说明平台差异。小程序通过现有前端角色路由，按宿主实际能力验收胶囊、键盘、底栏与返回。Apple 专用资料继续通过本机官方指导按需使用。
- REQ-003：三个宿主的插件都可发现技能，设计、Apple、Android、负责微信小程序的前端角色和 QA 按受影响的运行端选用。普通 Web、桌面和纯业务逻辑不预载，角色不获得额外权限或确认步骤。
- REQ-004：记录官方依据、参考项目的固定提交和各自许可。分发插件自行撰写的规范，保留项目既有技术栈、两步确认、原型和独立 QA。交付本地候选与验证结果。
- REQ-005：在现有 `xy-ui-design` 强化跨页面组件和语义设计变量的一致性，以及关键流程的失败、重试、取消、返回与完成反馈。Web、桌面、原生 App 和小程序按影响范围消费，复用项目已有规范和现有契约，保留合理的平台差异。

## 方案与原型关联

通用能力归入现有设计规则。移动专项入口保持简短，共享行为规则给出针对原型五段契约的写入方式，另设 Apple、Android 和微信小程序按需参考。以角色与共享 Skill 选择规则连接现有设计、实现和 QA，沿用包内来源校验与装配机制。两个验证场景作为契约案例使用，不新增实际产品原型或正式验收表单。

## 当前进展与恢复入口

本地候选已完成。通用规则和移动端入口随当前源码提供，后续按 [移动端技能入口](../../platforms/shared/skills/xy-mobile-ui/SKILL.md) 和 [通用设计参考](../../platforms/shared/skills/xy-ui-design/references/design-quality.md) 维护。候选留在本地等待后续发行安排。

## 验收结果与当前已交付行为

- Web、桌面、原生 App 与小程序共用跨页面一致性和关键流程恢复规则。原型使用已有五段契约，设计、开发、QA 沿用已有交接。
- `xy-mobile-ui` 在 Codex、Claude Code 和 Antigravity 候选包中可发现。按需选读 Apple、Android 或微信小程序参考。微信沿用 `xy-web` 发现与派发，不将普通浏览器测试作为微信宿主证据。
- 三端候选构建、包外资源读取、原有确认和 QA 门禁共 93 项回归通过。独立 QA 查出的微信引用版本和结果未明时的重试语义已修复，最终包的两项增量用例通过，独立复核通过。范围为插件装配、技能载荷和交付契约。

## 批准依据与必要证据

- 批准依据：用户在首版范围与官方规范蒸馏方式说明后指示“好，开始”，随后明确通用设计覆盖各平台，移动专项包括小程序，跨页面一致性列入本轮。
- 验收证据：`scripts/test_workflow.sh` 定点门禁 93 项通过，最终包的发现和包外资源两项增量通过。独立 QA 核对三个最终归档及来源摘要，并关闭两项整改。
- Apple、Android、微信及两份参考项目的复核依据见 [来源与许可](../../platforms/shared/skills/xy-mobile-ui/references/sources.md)。
