## 方案与原型关联

CLI 继续作为统一入口，TUI 调同一服务。保留当前 curses 样式与已获用户选择的直接开发路线；当前只读审计界定旧界面消费者，后续任务包采用实际 UI 影响，不扩建布局或视觉系统。

干净安装与旧版本升级是不同操作：先核实并保全必要用户配置，删除精确受管的旧文件，再以项目适配器和同一固定核心普通启用。已确认用户三个旧工作流／子代理任务均收尾。通用安全路径检查、当前 2.1 内任务旧 pin、事务恢复、三宿主原生差异属于有效能力，继续保留；不会为旧角色生成句或旧自包含核心补翻译／转换分支。

全新只读审计已经查明版本来源、兼容调用链、TUI 消费及精确清理范围。采用 product/VERSION 作为 2.1.0 的唯一人工版本来源，源码显示、本地核心及构建元数据据此校验；既存不可变核心保持原标签与字节。两个全新作者分别负责安装内核／版本／当前宿主 Hooks，以及 curses 旧投影清理／当前说明，写路径不重叠。核心与界面组合验证并冻结后逐个项目干净安装，最后统一 QA。当前仅已有用户级 CLI 和前置开发核心安装，不等于 2.1 交付。最终内容 ID 和三项目接入事实在真实验收后更新。
