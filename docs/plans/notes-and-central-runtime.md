## 方案与原型关联

中央目录复用管理器用户状态根：默认 ~/.config/agent-workflow/runtimes/内容ID，配置可沿现有 state-dir 入口指定。每版有规范 manifest.json 和 core，包含通用 product／roles／platforms／lib／scripts／templates／manager 及必要 setup，真实项目适配器、模型、权限和个人设置不进入核心。来源绝对路径不改变内容 ID。首版保留全部中央版本，不自动 GC。

内容库提供同一清单算法的只读来源预览与条件导入；CLI dry-run／TUI 预览不先写库，应用前比对来源前像。项目核心版本与任务绑定分开，内置固定逻辑命名空间通过严格 pin 解析，不把整个 .agent-workflow 换成链接或放宽通用安全读取器。

三宿主 Skill 链接目标为固定中央版本的 platforms/shared/skills/对应Skill，正文只在源码仓维护。启用／换版更新精确受管链接，停用移除入口链接、保留目标和仍需版本。项目原生角色／入口保留自身必要元数据及模型配置；原生父会话权限、MCP 与信任继续由宿主控制。文件生成、链接正确和静态校验不冒充模型实际加载。

CLI 是业务服务的统一调用方，TUI 复用该服务与预览／确认／取消流程。add 仅登记，add --enable 可显式同时启用；open／close 是 enable／disable 简写；del 解除管理前关闭新入口，不物理删除项目。直接动词明确执行意图，dry-run 只预览；既有 set／install／restore 的 apply 行为保持兼容。批量操作后续可复用接口，首版先完成单项目闭环。

TUI 属 UI-Flow／实际设计变化。用户已在具体简报后明确选择“沿用当前 curses 风格直接开发（推荐），保留真实 PTY 与完整 UI／可访问性 QA”；范围为项目登记／删除、启用／停用、选版、宿主状态及相应预览／恢复。无原型写入或视觉确认，工程／设计规则和生产 PTY 验证保留。复用当前命令面板、后台作业、中文宽度、窄终端和焦点约定，不替换全局视觉系统。

实现按真实依赖推进：内容库 → 任务 pin 与原生项目接入 → CLI 公共计划／应用服务 → TUI 消费。下游基于生产者已实际验证并冻结的公共 API 里程碑并行开发；合同证据通过不代表上游整个任务通过，最终请求 QA 仍等待所有实施者构建验证完成。高度共享同一适配器和安装合同，本轮沿当前工作区的精确路径所有权串并行，不建立重复候选源码树或业务环境。
