## 目标与范围

本轮按用户明确的样式及导航要求，为 TUI 增加包裹整个工作台的粗外边框与清晰内部分区，并改为 Tab／Shift+Tab 切换顶部平台、左右箭头切换项目与右侧内容区域。继续使用 Python 标准库与 curses，由职责实施者完成生产代码，唯一独立 QA 覆盖真实 PTY、界面与可访问性；新实例只接收当前完整任务包。

保留已验收的目录恢复、保存阶段反馈、按项目的工作流启停、来源与草稿保护和统一服务。本轮只改框架布局、按键路由、必要既有测试及说明；不实际修改三个业务项目、中央版本、凭据、权限或信任，不执行远端发布。工作区现有其他 Agent 的五份变更继续保留，不混入本轮提交。

## 方案与原型关联

沿用用户已选定的 curses 直接开发路线。本次为明确要求的局部外框与导航升级（UI-Patch），不生成或更新原型，保留生产 UI 与可访问性 QA。粗框使用与现有 Unicode 字符格一致的粗线字形及现有语义样式，内部保留适当的细分隔；复用 Theme、Layout 和弹层，不建立新的颜色系统或设计规范。

Layout 统一给外框、内容起点、内部分隔和底部提示留位，主界面、弹层、鼠标命中与光标共享真实坐标。不得简单把粗线覆盖在原文字之上。Tab／Shift+Tab 复用现有平台切换语义；左右按方向设置区域焦点，不再改变角色模型列。输入与弹层先处理自身按键，避免误触后台管理动作。

实施者只拥有 manager/tui.py、manager/tui_support.py、tests/test_manager_tui.py、tests/test_workflow_manager.py 及 README.md。tests/test_workflow_manager.py 已发现一个将 Tab 用作切区的真实调用者，须同步更新。目录、服务和原生协议无需修改。测试复用现有最小项目及 PTY，保留必要原始字节与稳定字符格；不复制整仓或操作真实业务项目。
