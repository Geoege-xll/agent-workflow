## 目标与范围

维护项目、三宿主角色模型及配置恢复的统一管理入口。本轮按用户实测反馈修复 Codex 模型目录失效／暂时读取失败后无法恢复的问题，完善模型与推理设置的保存反馈、项目列表分隔和选中项目的工作流启停入口。继续使用 Python 标准库与 curses，由原生实施者完成生产代码，唯一独立 QA 覆盖真实 PTY、界面及可访问性；新实例只接收当前完整任务包。

保留既有模型来源、身份／提供方隔离、草稿冲突保护、备份恢复以及 CLI／TUI 统一服务。仅改当前管理器、相关既有测试和说明；不实际修改三个业务项目的模型或启停状态，不重装／切换中央版本，不调用模型推理，不调整凭据、权限或信任，不执行远端发布。其他 Agent 提供的生产 UI 验收修复及其交接报告单独只读评估，未采纳前不混入本轮 TUI 提交。

## 需求与验收

| 需求 | 当前行为与验收边界 |
|---|---|
| REQ-001 目录恢复 | 区分完整目录、来源失效及读取失败。正常跨宿主切换复用成功目录；用户重新进入模型／推理编辑时复核本地来源，失败或失效才有界重查，不永久停留于继承／当前配置后备项 |
| REQ-002 来源保护 | 不硬编码模型、不采用未知归属缓存，不重绑旧草稿的来源及编辑基线；预览仍拒绝旧来源草稿，显示重选或丢弃的恢复动作。draw／options／预览／事务锁内不启动原生查询 |
| REQ-003 保存反馈 | 选择后明确“已暂存、尚未保存”；s 展示保存预览，确认后才备份写入。无改动、执行中、成功、失败、取消与冲突都有准确反馈，失败保留草稿，帮助及 README 与实际按键一致 |
| REQ-004 项目分隔 | 项目名称、状态与版本层次清晰，条目之间有分隔；选择与焦点不混淆。长中文路径、搜索、滚动、鼠标命中、55×16 窄屏及单色模式保留可用入口 |
| REQ-005 工作流启停 | 主界面显示选中项目工作流状态与明确启用／停用入口，使用现有 service 的只读预览、确认和事务。状态未知或存在冲突不假报成功，不误改其它项目、文档或模型草稿 |
| REQ-006 验证与评估 | 在既有测试补真正缺失的恢复场景，复用仍有效守卫验证，完成实际 PTY 的保存／失败／取消／项目启停及窄屏路径。独立评估用户提供的 mt-shop 交接报告，不将其业务目标或历史 PASS 扩大为本次验收 |

## 方案与原型关联

沿用用户此前选定的 curses 直接开发路线，本次为现有界面的局部交互升级（UI-Patch）；不生成或更新原型，保留完整生产 UI 与可访问性 QA。复用 manager/tui_support.py 的 Theme、Layout、字符格与弹层约定；使用现有组件和语义颜色，不建立新视觉系统或新增设计规范。

manager/catalog.py 只补充内部结构化目录状态，保留已有输出合同；manager/tui.py 在用户明确进入编辑时恢复目录，在渲染和来源守卫阶段不重复启动宿主。模型／推理选择保留当前项目、宿主、角色身份；保存成功必须来自真实服务完成和校验，不以无草稿或非空来源摘要充当成功。启停继续调用现有项目计划和应用服务，不新增登记库写入路径。

实施者拥有 manager/tui.py、manager/tui_support.py、manager/catalog.py、tests/test_manager_tui.py、tests/test_workflow_manager.py 以及 README.md 中受影响的管理器说明。测试复用现有最小安装及 PTY 夹具；为安全验证启停和写入，使用测试自身必要的最小临时项目与宿主配置，不复制整仓，不触碰真实项目。可复用的定向检查只补真实缺口，最终唯一 Reviewer 审核冻结差量及完整证据。

## 验收结果与当前已交付行为
