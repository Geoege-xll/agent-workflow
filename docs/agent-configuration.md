# 原生 Agent 配置工具

本工具按用户已批准的独立配置路线开发，与 Agent Workflow 3.0 分别交付。它管理 Codex、Claude Code、Antigravity 的原生 Agent 模型与推理设置；不要求安装工作流、中央登记或固定七个工作流角色。Windows 继续暂停，界面跨平台复用不代表原生文件操作已在 Windows 验收。

## 职责与版本

配置核心只实现一次发现、字段校验、读取、预览、条件保存、恢复和诊断。网页通过本机 HTTP 使用它；命令行脚本复用相同核心；MCP 保留为按需开启的接入方式。普通网页配置和脚本查询无需 MCP。工作流核心不导入服务，也不读取服务版本。

独立核心位于 `native_config/`，版本源为该目录的 `VERSION`，当前已正式发布 `0.1.1`，插件固定描述已在真实下载核验后标记 published。实际资产见[独立发行](https://github.com/Geoege-xll/agent-workflow/releases/tag/native-agent-config-v0.1.1)。HTTP、网页、脚本和可选 MCP 共用该核心。早期 `plugin_runtime/`、插件可选服务装配和专属旧测试已清理；插件不包含服务或网页，也不把旧 AWF 七角色 JSON 偏好迁移为原生配置。

## 插件内打开

维护 Skill 为 `xy-config`，显示“模型配置”。Claude Code 使用 `/xy-workflow:xy-config`；Codex 在 `/skills` 或 `$` 选择器选择插件的实际发现项；AGY 当前载荷使用 `/xy-config`，以客户端实际发现项为准。省略动作等价 open：

| 动作 | 用户可见行为 |
| --- | --- |
| open | 定位当前平台和明确的项目，验证组件与服务后尝试打开浏览器 |
| status | 只读报告组件、服务和范围，不准备组件或启动服务 |
| doctor | 只读诊断依赖、发行完整性、来源及连接，不刷新模型目录或调用官方客户端 |

仅主会话中用户显式调用维护 Skill 才进入该路径；讨论“实现 xy-config”等业务需求仍走原业务流程。维护操作不读取整份 WORKFLOW、不建任务图、不派代理。普通工作流无需配置组件或 MCP。

首次缺组件时先显示待准备信息，用户确认后才执行固定准备动作。组件来自发行描述指定的真实独立包；校验 SHA、ZIP 和 BUILD 完整闭包后，放入用户级不可覆盖版本目录并原子登记。未发布描述没有下载地址，不尝试猜测地址；明确提供离线 ZIP 也必须匹配固定摘要。安装失败保留旧活动版本，更新不覆盖旧服务正在使用的程序目录。

插件缓存只保存薄入口、固定组件描述和维护 Skill。组件程序、真实发行快照与 registry 位于 `~/.local/share/agent-workflow/components/native-agent-config/`；配置服务的连接及恢复资料仍使用独立数据目录。代码、运行态和业务项目分开存放，不改 PATH、HOME、认证、宿主信任或项目根指令文件。

成功回执分别报告服务与浏览器状态。浏览器打开失败时服务仍为 ready，并保留 0600 的私有 HTML 打开入口；重新运行命令可重取入口，不会因浏览器失败重装组件或重启健康服务。普通机器回执不包含认证片段，status/doctor 不创建链接文件或修复权限。

## 配置对象与写入范围

发现结果区分宿主、原生名称、用户/项目/插件来源、真实文件身份、调用名称和有效状态。同名对象并列展示，内部使用稳定 ID；不把不同来源按名称合并。尚未观察的 CLI 会话角色、托管策略或插件启用状态必须保持未知，不能扫描缓存就宣布已安装并生效。

用户级和项目级的受支持原生定义可以修改 `model` 与对应宿主推理字段。插件缓存只读；没有官方覆盖接口时明确不可编辑。模型、推理级别和重载方式按宿主能力处理。项目级完整定义覆盖用户级定义的语义，不能用旧工作流的逐字段偏好合并算法代替。

页面默认进入“调用偏好”，另有“原生定义文件”模式。后者的“用户级”表示用户级完整 Agent 定义，并不等价于 Codex `[agents]` 的统一子代理默认设置；本工具不会改写该设置来冒充逐角色配置，也不会把插件缓存变成可写覆盖。

清除字段表示恢复该宿主的实际继承，不删除 Agent 提示词、工具约束或其他配置。保存必须保留非目标字段、注释、正文和换行；复杂格式无法安全定位时明确拒绝。路径由服务端当前发现结果决定，网页或 MCP 不提供任意文件写入入口。

## 本机模型目录与推理选项

模型目录在首次进入编辑、显式刷新或来源失效后的预览前按需读取，普通渲染不反复启动客户端。同来源可复用缓存；客户端、提供方、身份元数据或目录配置改变后，旧候选失效，用户草稿保留。context 的 `catalog_source_stamp` 与目录的 `source_stamp` 使用同一语义，和配置保存 revision 分开；来源暂不可读时明确显示未知，不给旧目录续盖新来源。

| 平台 | 读取来源 | 能力边界 |
| --- | --- | --- |
| Codex | 实际 PATH 中客户端的原生 `model/list`，或用户明确配置的 `model_catalog_json` | 使用模型实际返回的推理档位、显示名称与可见性。默认模型缓存只提供身份失效信号，不当作候选清单。 |
| Claude Code | 实际配置根、用户菜单、当前模型、项目与 local 设置及白名单环境的别名映射 | 配置出现不代表账户可调用；完整 ID 可以用于受支持原生定义，调用覆盖只接受相应官方别名。 |
| Antigravity | 本机官方 `agy models` | 完整会话模型 ID 另标 session-only，不能直接写入自定义子代理 tier；独立推理与调用 schema 未确认时明确保留限制。 |

每行按自己的有效草稿模型重算推理候选，不把多个模型能力求并集。模型变更不顺便清除已有 effort；不兼容值保留并要求重选或显式清除。跨模型只批量修改 effort 时使用已知能力的交集。未知能力与目录读取失败都有单独说明，不伪装实际运行通过。

## 子代理调用偏好

调用偏好是工具维护的派发设置，与官方原生 Agent 完整定义分开。即使当前没有可写原生文件，通用默认目标仍可设置；逐 Agent 使用真实 `invoke_name`，插件来源保持限定调用名，不限于工作流内置角色。未被发现的历史身份可以清除，但不会被标为已可派发。

偏好保存在各宿主实际用户配置根下的 `native-agent-config/dispatch-preferences.json`。用户和项目记录在同一个宿主文件内按真实项目物理绝对路径隔离；不向业务项目复制角色、指令或第二份规范，不依赖组件版本目录或服务 data_dir。

逐字段按用户通用、用户该 Agent、当前项目通用、当前项目该 Agent 解析；缺失字段继承，清除本层字段后恢复下层。显式模型 `inherit` 表示不向原生调用传模型覆盖，不是一个模型 ID。原生完整定义及宿主其他配置仍按各自官方优先级处理。

保存前先形成最终事务，再校验当前上下文实际受影响的有效模型／推理组合。改变通用默认会检查受影响的继承目标，相同最终编辑不受顺序影响；不自动清除 effort，也不拿当前目录能力冒充其他项目的目录。

PM 在派发前读取同源纯标准库解析器，只有当前宿主真实工具支持时才映射参数。没有偏好时沿宿主默认；损坏文件或无法表达的已配置字段明确阻断相应派发，不静默丢弃。Codex 通用 fresh 入口读取通用偏好，不能拿任务标签冒充原生角色身份；Claude 的调用别名、版本门槛与实际 effort 参数分别检查；AGY 不生成未经证实的调用字段。

偏好保存回执表示“已保存、供下一次派发读取”，不要求常驻 HTTP/MCP，也不修改当前主会话或正在执行的 Agent。此状态不等于原生定义文件的“等待重新加载”，更不等于指定模型实际运行已验证。

## 工作流启停

同一网页的“工作流启停”分类独立管理该事务，和 Agent 模型字段分开。用户级可选择官方默认／启用／停用，项目级可选择继承／启用／停用；继承只移除本层目标键，不删除文件或写入字符串 inherit。只有已识别且来源明确的工作流插件可编辑，来源未知或有歧义时显示原因，不扫描缓存推断已安装或实际生效。

| 平台 | 用户级目标 | 当前项目目标与边界 |
| --- | --- | --- |
| Codex | 实际 CODEX_HOME 下的 config.toml | `.codex/config.toml` 的目标插件 enabled 布尔值；项目须受信任，宿主更高层策略、启动参数和 Hook 信任仍按官方规则处理。 |
| Claude Code | 实际 CLAUDE_CONFIG_DIR 下的 settings.json | `.claude/settings.local.json`，明确为仅本机当前项目；清除 local 覆盖后先继承 `.claude/settings.json`，再继承用户设置，未观察的默认值保持未知。 |
| Antigravity | 只读说明 | 尚无足够官方文件合同支持本工具的项目三态写入，显示不支持及官方管理说明，不用全局命令冒充项目操作。 |

各平台分别保存。启停、调用偏好、原生定义使用三类独立草稿和预览，一次保存不混合操作；保存只清除对应草稿，错误、重新读取和切换范围均保留草稿归属。服务端重新核对目标、继承来源与前像；首次创建固定配置路径也在确认应用后执行，外部抢建或来源变化会拒绝旧预览。失败时展示实际创建／发布和恢复资料，位置未知只显示原声明位置，不宣称完全回滚或自动删除。

停用整个插件后，该项目可能无法再调用插件的 xy-config Skill。停用前应保存页面提供的独立重新打开命令，或通过客户端官方插件管理恢复启用。独立命令定位当前包内脚本，保留原项目、配置根和状态根；显式 home 与环境选根分别处理，只限定新进程的必要环境，不修改全局环境或复制令牌。包内入口在插件停用后仍可用，不需要新安装器。

保存只改变磁盘设置，需要新会话消费；已有会话不会自动清除工作流上下文或中断任务。“重新读取”仅回读配置，不代表宿主已重新加载或真实工作流已验证。具体实现、验收和平台能力边界见[项目启停计划](plans/workflow-project-activation.md)。

## 预览、应用与状态

编辑先形成不写文件的预览，应用同一个服务端计划并重新核验来源与前像。文件改变、来源改变或并发保存会使旧计划失效。批量写入在全部校验后执行，失败精确报告已完成/恢复情况；不承诺跨文件系统的断电原子性，也不删除唯一恢复资料。

发布使用实际对象隔离、前像核验与排他创建，目标重新出现时拒绝覆盖。为保护编辑器提前打开的旧文件句柄，成功保存和回滚也保留真实隔离对象与独立预览副本，放在私有目录；正常返回恢复资料不等于保存失败。`preview_preimage` 的 SHA 表示固定预览字节；`isolated_object` 的 SHA 只表示隔离时观察值，原对象仍可能被旧句柄继续写入，不能称为当前不可变备份。当前未提供自动清理这些原对象的合同，不按保存成功自动删除它们。

最终检查或目录退出异常时，界面保留已发生发布、逐项结果和恢复资料，说明完整请求尚未获最终确认；不会把它误报为完全没有写入。目录移动导致当前位置无法核实时，`backup` 为 `null`，`declared_backup` 仅记录原声明位置，`location_status` 为 `unknown`，并保留观察身份供人工核对。此时先保存收据并确认文件位置，再重新读取；原预览已消费，不能重复应用。服务不会扫描其它目录猜测新位置。

状态分别表示：

- 已保存：原生配置文件已按预览写入。
- 等待重新加载：客户端或后续新 Agent 尚需消费这些配置。
- 实际运行已验证：只有来自真实宿主的相应执行证据才能声明；静态文件、API 成功或参数投影均不足以证明。

## 网页交互范围

alpha.5 工作台采用获准的浅色紧凑布局：顶部平台，横向“模型与推理／工作流启停／诊断与帮助”分类，统一用户级／项目级范围与按需项目路径；通用默认独立，动态 Agent 表格突出真实身份、模型、推理和本层状态。原生定义在高级入口单独编辑，不与调用偏好混合保存。源码已独立验收，真实发行、本机安装及完整性检查完成，具体边界见[交付记录](plans/native-model-preferences.md)。

平台／范围／分类切换直接保留草稿；当前事务底部统一提供放弃与预览保存。确认放弃后焦点回可操作字段，取消／Esc 回原触发器；来源冲突和部分发布的原始收据可以重新打开。模型使用原生输入与候选目录，保留自定义 ID、空目录及未知已保存值；无法从当前 context 得知被遮蔽继承时明确等待服务端预览，不猜值。只读对象与原因明确可见，旧异步响应不能覆盖新范围，目录刷新失败不能重置已有模型。

本地 HTTP 仅监听回环并验证请求；静态页面不加载远程资源。服务关闭先等待活动查询/保存结算，再清理本实例连接记录并释放锁。等待正文或尚未进入业务的慢连接会被取消，目录查询保留超时与自有进程组回收。

## 源码使用与独立打包

需要本机已有 Python 3.11+ 和 Bash，不安装解释器、不修改 PATH。源码目录可运行：

```bash
bash scripts/agent_config.sh open --host codex
bash scripts/agent_config.sh status --host codex
bash scripts/agent_config.sh doctor --host codex
bash scripts/agent_config.sh list --host claude
bash scripts/agent_config.sh list --host codex --project /absolute/project
bash scripts/agent_config.sh resolve --host codex --role <list返回的AgentID>
bash scripts/python_runtime.sh -B -X utf8 native_config/preference_contract.py --host codex --agent '*'
```

最后一条只读解析通用调用偏好；传实际原生调用名可解析逐 Agent，当前项目加 `--project /absolute/project`。插件中使用固定物理根的 `source_pack.py dispatch-preferences` 入口，不能拿业务任务标签充当原生身份。它不启动配置服务，错误返回非零且不输出原始私密内容。

安全 `open` 默认尝试打开网页；`--no-browser` 只准备私有打开入口。open/status/doctor 返回稳定 JSON，地址不带认证片段，服务就绪与浏览器结果分别结算。启动锁、首行读取、健康握手及失败自有子进程回收使用有限总预算；版本或配置根不一致时不强制复用、终止旧服务。

原 `console`、`serve` 和 MCP 接口保留。开发者直接使用 console 时，其输出 URL 的片段包含访问令牌，应按本地配置入口处理；插件薄入口调用安全 open，不转发原 console 输出。`serve --port 0 --idle-timeout 1800` 可前台运行。默认读取本机真实原生配置，保存会修改所选的可写原生定义。

测试须使用显式临时根，与真实用户配置隔离：

```bash
bash scripts/agent_config.sh open --no-browser --host codex \
  --home /absolute/test-home --data-dir /absolute/test-state
```

`--home` 只允许启动入口固定，不接受 HTTP/MCP 任意改写；同状态目录不同 home 不复用服务。无需改写 `HOME` 或 `CODEX_HOME`。

离线独立包构建：

```bash
bash scripts/python_runtime.sh -B -X utf8 packaging/build_agent_config.py \
  --output-dir /absolute/new-output-directory
```

解压后可从任意目录运行包内 `scripts/agent_config.sh`，不需要工作流源码、manager 或插件。普通网页使用无需 MCP；只有主动运行 `mcp` 子命令才启用 stdio 接口，不自动注册客户端。目前未提供跨进程的 preview/apply 脚本命令，网页保留同一服务端计划完成预览与应用。

维护者可用 `packaging/build_config_distribution.py --artifact <真实ZIP> --output <descriptor>` 从真实包生成未发布发行描述。加入 `--url <已发布资产URL>` 时，工具必须实际下载并核对同一 SHA/BUILD 后才写 published，没有跳过在线核验的参数。alpha 包始终标为 alpha，不能冒充稳定发行；插件业务流程不等待组件发布或启动。

## 当前验证与限制

核心、传输、独立包和真实浏览器已完成作者验证。浏览器覆盖三个平台的临时原生定义、同名来源、只读插件、清除字段、错误保留草稿、批量部分失败及恢复资料、键盘操作和窄屏。上述测试不读取或修改用户真实配置。

当前源码的原生读写、条件发布、退出结算、清单身份、传输和网页各有临时真实夹具与负控，具体命令、范围、退出码及独立 QA 状态统一记录在[3.0 计划](plans/plugin-v3.md)。源码与临时保存流程的证据不替代官方客户端实际模型执行验收。部分失败与恢复冲突须保留逐项收据和唯一前像，不能展示为全部成功。
