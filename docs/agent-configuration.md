# 原生 Agent 配置工具

本工具按用户已批准的独立配置路线开发，与 Agent Workflow 3.0 分别交付。它管理 Codex、Claude Code、Antigravity 的原生 Agent 模型与推理设置；不要求安装工作流、中央登记或固定七个工作流角色。Windows 继续暂停，界面跨平台复用不代表原生文件操作已在 Windows 验收。

## 职责与版本

配置核心只实现一次发现、字段校验、读取、预览、条件保存、恢复和诊断。网页通过本机 HTTP 使用它；命令行脚本复用相同核心；MCP 保留为按需开启的接入方式。普通网页配置和脚本查询无需 MCP。工作流核心不导入服务，也不读取服务版本。

独立核心位于 `native_config/`，版本源为该目录的 `VERSION`，当前为 `0.1.0-alpha.2`。HTTP、网页、脚本和可选 MCP 已切换到该核心。早期 `plugin_runtime/`、插件可选服务装配和专属旧测试已清理；不把旧 AWF 七角色 JSON 偏好升级或冒充原生配置。

## 配置对象与写入范围

发现结果区分宿主、原生名称、用户/项目/插件来源、真实文件身份、调用名称和有效状态。同名对象并列展示，内部使用稳定 ID；不把不同来源按名称合并。尚未观察的 CLI 会话角色、托管策略或插件启用状态必须保持未知，不能扫描缓存就宣布已安装并生效。

用户级和项目级的受支持原生定义可以修改 `model` 与对应宿主推理字段。插件缓存只读；没有官方覆盖接口时明确不可编辑。模型、推理级别和重载方式按宿主能力处理。项目级完整定义覆盖用户级定义的语义，不能用旧工作流的逐字段偏好合并算法代替。

清除字段表示恢复该宿主的实际继承，不删除 Agent 提示词、工具约束或其他配置。保存必须保留非目标字段、注释、正文和换行；复杂格式无法安全定位时明确拒绝。路径由服务端当前发现结果决定，网页或 MCP 不提供任意文件写入入口。

## 预览、应用与状态

编辑先形成不写文件的预览，应用同一个服务端计划并重新核验来源与前像。文件改变、来源改变或并发保存会使旧计划失效。批量写入在全部校验后执行，失败精确报告已完成/恢复情况；不承诺跨文件系统的断电原子性，也不删除唯一恢复资料。

发布使用实际对象隔离、前像核验与排他创建，目标重新出现时拒绝覆盖。为保护编辑器提前打开的旧文件句柄，成功保存和回滚也保留真实隔离对象与独立预览副本，放在私有目录；正常返回恢复资料不等于保存失败。`preview_preimage` 的 SHA 表示固定预览字节；`isolated_object` 的 SHA 只表示隔离时观察值，原对象仍可能被旧句柄继续写入，不能称为当前不可变备份。当前未提供自动清理这些原对象的合同，不按保存成功自动删除它们。

最终检查或目录退出异常时，界面保留已发生发布、逐项结果和恢复资料，说明完整请求尚未获最终确认；不会把它误报为完全没有写入。目录移动导致当前位置无法核实时，`backup` 为 `null`，`declared_backup` 仅记录原声明位置，`location_status` 为 `unknown`，并保留观察身份供人工核对。此时先保存收据并确认文件位置，再重新读取；原预览已消费，不能重复应用。服务不会扫描其它目录猜测新位置。

状态分别表示：

- 已保存：原生配置文件已按预览写入。
- 等待重新加载：客户端或后续新 Agent 尚需消费这些配置。
- 实际运行已验证：只有来自真实宿主的相应执行证据才能声明；静态文件、API 成功或参数投影均不足以证明。

## 网页交互范围

平台切换、用户级/当前项目范围、原生 Agent 清单、来源和同名冲突、模型/推理编辑、批量预览应用、清除覆盖、目录刷新和诊断。只读对象与原因明确可见；错误保留草稿，旧异步响应不能覆盖新范围，目录刷新失败不能重置已有模型。

本地 HTTP 仅监听回环并验证请求；静态页面不加载远程资源。服务关闭先等待活动查询/保存结算，再清理本实例连接记录并释放锁。等待正文或尚未进入业务的慢连接会被取消，目录查询保留超时与自有进程组回收。

## 源码使用与独立打包

需要本机已有 Python 3.11+ 和 Bash，不安装解释器、不修改 PATH。源码目录可运行：

```bash
bash scripts/agent_config.sh console --host codex
bash scripts/agent_config.sh list --host claude
bash scripts/agent_config.sh list --host codex --project /absolute/project
bash scripts/agent_config.sh resolve --host codex --role <list返回的AgentID>
```

`console` 默认尝试打开网页，`--no-browser` 只输出本地地址；地址片段包含访问令牌，应按本地配置入口处理。`serve --port 0 --idle-timeout 1800` 可前台启动服务。默认读取本机实际用户配置，保存会修改所选的可写原生定义。

测试须使用显式临时根，与真实用户配置隔离：

```bash
bash scripts/agent_config.sh console --no-browser --host codex \
  --home /absolute/test-home --data-dir /absolute/test-state
```

`--home` 只允许启动入口固定，不接受 HTTP/MCP 任意改写；同状态目录不同 home 不复用服务。无需改写 `HOME` 或 `CODEX_HOME`。

离线独立包构建：

```bash
bash scripts/python_runtime.sh -B -X utf8 packaging/build_agent_config.py \
  --output-dir /absolute/new-output-directory
```

解压后可从任意目录运行包内 `scripts/agent_config.sh`，不需要工作流源码、manager 或插件。普通网页使用无需 MCP；只有主动运行 `mcp` 子命令才启用 stdio 接口，不自动注册客户端。目前未提供跨进程的 preview/apply 脚本命令，网页保留同一服务端计划完成预览与应用。

## 当前验证与限制

核心、传输、独立包和真实浏览器已完成作者验证。浏览器覆盖三个平台的临时原生定义、同名来源、只读插件、清除字段、错误保留草稿、批量部分失败及恢复资料、键盘操作和窄屏。上述测试不读取或修改用户真实配置。

当前源码的原生读写、条件发布、退出结算、清单身份、传输和网页各有临时真实夹具与负控，具体命令、范围、退出码及独立 QA 状态统一记录在[3.0 计划](plans/plugin-v3.md)。源码与临时保存流程的证据不替代官方客户端实际模型执行验收。部分失败与恢复冲突须保留逐项收据和唯一前像，不能展示为全部成功。

复杂 YAML 无法安全定位时拒绝编辑；未文档化或未观察到的来源保持诊断；AGY 调用 schema 未确认时不生成派发参数。目录查询和保存不证明当前官方客户端已重载或按所选模型实际执行。当前不是稳定发行或完整原生运行验收结论。
